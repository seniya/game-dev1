# Living Small World

현재 **v0.11**: 기본 **12명**이 **48×36칸**의 넓은 마을에서 시작합니다. 기존 32×24칸 대비 마을 면적은 2.25배입니다. 지도 아래 **관찰 과제**에서 도움 3번·친밀도 10 이상 관계 3쌍·식량 생산 24개를 확인하고, 실제 사건으로 이동할 수 있습니다. **새집/농장 짓기**는 선택한 마을의 공동 목재 12/16개를 사용하며 서버가 검증·기록합니다. 기존 저장 세계의 인구와 지형은 유지합니다. **12명의 넓은 마을로 시작**을 누르면 이전 세계를 백업하고 새 구성을 적용합니다. **기본 자원 14종·가공 상품 12종·직업 26종**과 아동·은퇴·요양·구직 무직 상태를 제공합니다. **NPC 만들기**에서 이름·나이(0~80)·직업·목표·배경, 피부/머리/옷 색상·머리 모양·안경/모자, 성격·욕구·생활 기술·교육·산업 숙련과 시작 자산을 설정하여 기존 세계에 주민을 추가합니다. 입주할 집과 첫 인사 상대를 고르고, 생성 후 **선택 주민 따라보기**에서 실제 이동·대화·도움·거래와 관계 변화를 관찰합니다. **마을 주민 → 내가 만든 주민만 / 주민 검색**으로 다시 찾을 수 있습니다.

지도는 **정착지 전체 / 세계 전체 / 선택 주민 따라보기**를 지원합니다. 주택은 건물 단계에 따라 높이가 달라지고, 주거 유형별 지붕과 화단으로 구분합니다. 시장은 차양과 진열대, 창고는 적재물과 대문, 우물은 두레박, 농장은 작물, 산업체는 이름표와 작업 소품으로 표시합니다. 건설된 도로 시설과 실제 운송 위치, 지역 공공서비스 수준도 표시합니다. 공공서비스는 지역 단위 지표이며 존재하지 않는 개별 병원·학교 부지를 만들어 그리지 않습니다. 기존 세계의 인구와 자산은 유지하며 작은 마을이 업데이트만으로 도시로 바뀌지는 않습니다.

지도에서 **주민·건물·자원을 클릭**하거나 **시설·자원 선택** 목록을 사용하면 확대 관찰과 정보 패널이 열립니다. 주택의 거주자·소유자·정원, 해당 정착지 시장의 가격·재고와 공동 창고 물자, 작업장의 고용·누적 생산, 농장의 생장량, 자원의 잔량·고갈 상태를 확인할 수 있습니다. 관련 주민을 누르면 주민 관찰로 돌아갑니다. 선택은 관찰 화면만 바꾸며 서버 세계나 마을 정책을 변경하지 않습니다. 이름표는 실제 화면 크기를 기준으로 겹침을 검사하고, 선택·마우스를 올린 대상과 주민을 우선 표시합니다. 공간이 부족한 일반 이름표와 상태 배지는 숨기며, 시설 목록과 정보 패널에서는 전체 이름을 확인할 수 있습니다.

캐릭터는 이동 보행, 수면 자세, 작업 도구·앞치마, 식사·음수 소품으로 행동을 표현합니다. 건강·통증·질병·부상, 갈증·배고픔·피로·온기에 따라 상태 배지가 바뀌고 프로필에도 같은 상태가 표시됩니다. 외형은 기존 머리·옷·액세서리를 유지하며 아동 크기와 고령자의 머리 디테일을 반영합니다. 이동 중에는 목적지의 작업·수면 자세를 미리 표시하지 않습니다. 동작 줄이기 설정에서는 보행 변화를 생략합니다.

NPC는 빈 주거(이주 예약 포함)가 있을 때 입주하며 생존 3,000명·전체 인물 30,000명 상한을 따릅니다. 시작 자산은 별도 입주 회계와 원본 사건에 기록됩니다. 첫 인사는 실제 경로를 따르는 시도이며 상대의 이동·상태에 따라 실패할 수도 있습니다. 소개글은 프로필용이며 새로운 행동 규칙이나 모델 프롬프트 명령이 아닙니다. 기존 주민과 같은 규칙으로 살아가고 AI 없이도 동작합니다. 서버 검증·중복 명령 방지·원자적 저장·복원 및 기존 v1~v5 저장 읽기를 유지하며, v5에 선택적 profile/입주 회계 필드를 추가했습니다.

v0.8의 도시 연대기·가계도·생태·공동체와 검증 범위는 [HERITAGE.md](HERITAGE.md), 이전 도시 규칙은 [URBANISM.md](URBANISM.md), 이번 검증 결과는 [TASKS.md](TASKS.md)를 참고하세요. 아래 버전별 설명은 이전 구현 기록입니다.

## 실행

Node.js 22.12 이상(검증 환경: 24.16), npm이 필요합니다.

```bash
npm ci
npm run dev
```

터미널에 표시되는 주소를 브라우저에서 엽니다. 기본 주소는 `http://localhost:5173`입니다. 외부 LLM 계정이나 API 키는 필요 없습니다. 웹폰트를 불러오지 못해도 시스템 글꼴로 동작합니다.

```bash
npm run build
npm run preview
```

## 서버에 이어지는 세계 (v0.3)

기본 화면은 같은 소유자 계정의 모든 기기에서 하나의 서버 세계를 봅니다. 세계 상태·시계·명령 처리는 Cloudflare Worker, 체크포인트·사건 아카이브는 D1에 보관합니다. 배포 사이트의 **소유자 전용 비공개** 접근 정책이 화면과 API 모두에 적용됩니다.

- 처음에는 일시정지입니다. 재생·정지·배속·실험 결과는 모든 기기에 반영됩니다. 관측 중 약 2초마다 동기화합니다.
- 서버 지도는 확인된 이동 경로를 응답 간격에 맞춰 보간하며, 기본 700ms의 재생 여유를 두어 통신 지연으로 인한 멈춤을 줄입니다. 느린 응답에서는 여유를 늘리되 재생 구간은 최대 6초로 제한합니다. 응답이 오래 끊기면 마지막 확인 위치에서 멈추고, 일시정지·세계 교체·동작 줄이기 설정에서는 즉시 현재 위치를 표시합니다. 동기화는 한 번에 하나씩 요청하며, 느린 요청 뒤에는 남은 주기만 기다리고 AI 상태 조회는 별도로 진행합니다.
- **자리를 비워도 진행**은 기본으로 꺼져 있습니다. 마지막 관측 요청에서 15초가 지나면 비접속으로 간주합니다. 켜면 다음 접속의 첫 동기화에서 서버 시각으로 경과량을 계산하고 최대 게임 하루(144틱)만 반영합니다. 상한 이후 시간은 버립니다. 정기 백그라운드 작업을 계속 실행하는 방식이 아닙니다.
- 화면 동기화에서는 확정된 상태 변경분과 명령·사건을 저장합니다. 전체 체크포인트는 30회 커밋/60초/변경분 1MB 조건에서 갱신하며, 서버 재시작 시 이후 변경분을 적용해 복원합니다.
- 명령 ID와 상태 리비전으로 네트워크 재시도와 동시 접속의 중복 처리를 막습니다. 다른 기기가 먼저 변경하면 최신 상태를 표시하고 해당 조작을 다시 선택하도록 안내합니다.
- **불러오기**에서 기기 저장 또는 JSON을 서버로 가져옵니다(10MB 이하, 생존 3,000명까지). 가져오기·시드 초기화 전에 서버의 이전 세계를 백업합니다. 기존 기기 저장은 자동으로 덮어쓰지 않습니다.
- 사건은 주민·날짜·원인 색인으로 조회하며 ID/내용 검색을 지원합니다. 한 페이지 40건, 화면에는 최대 400건만 유지합니다. 사건 상세에서 원인과 이후 선택을 서버로부터 조회합니다. JSON 내보내기에는 전체 이력이 포함됩니다.
- **기기 세계 관찰**(`/?local=1`)은 기존 localStorage/파일 실행 모드입니다. 서버와 자동 병합하지 않습니다. 서버 연결 실패 시 상태를 임의로 새 세계로 바꾸지 않습니다.

개발 서버도 실제 Worker 런타임과 로컬 D1을 사용합니다. 개발 데이터는 `.wrangler/`에 저장되며 재시작 후 복원됩니다. `npm run build`는 `dist/server/`의 Worker와 `dist/client/`의 UI를 함께 만듭니다. 배포 구조와 검증 근거는 [SERVER_WORLD.md](SERVER_WORLD.md)를 참고하세요.

## 서버 모델과 기억에 근거한 말 (v0.4)

관찰 실험실에서 **AI 끄기 / Mock / 서버 모델**을 선택합니다. 설정 전에는 Mock으로 무료 관찰하며 서버 모델 선택은 비활성화됩니다. Ollama 또는 구조화 JSON Chat Completions 호환 서버를 연결할 수 있습니다. 개발용 설정은 `.dev.vars.example`, 배포 설정과 제한은 [LLM_ARCHITECTURE.md](LLM_ARCHITECTURE.md)를 참고하세요. 키는 서버 secret으로만 관리합니다.

중요한 사건에서 허용된 목표와 해석을 제안하며 관계 화면의 **기억에 근거한 말 듣기**는 해당 주민이 상대와 함께한 기억을 인용합니다. 결과는 개인의 해석으로 표시하고 원본 사건에 연결합니다. 모델은 자원·위치·관계 수치를 변경하지 않습니다. 응답이 늦거나 실패해도 세계는 계속됩니다.

실제 날짜별 기본 24회(실패·재시도·대화 포함), 동시 호출 1개, 12초 timeout, 최대 두 번 재시도, 응답당 700토큰을 제한합니다. 모드 전환/초기화 후의 오래된 응답은 폐기하고 호출 예산은 초기화하지 않습니다. 실험실에서 처리 상태·보고된 사용량·개별 판단 입력/결과 JSON을 확인합니다. API 호환성과 장애 처리는 제어된 HTTP 응답으로 검증했으며, 실제 모델의 품질과 공급자별 지원은 연결한 환경에서 확인해야 합니다.

## Chrome 목표 선택 시험 구현 (v0.5)

**6A는 사용자 수용 완료이며 추가 실기기 자동 추론 검증과 구분합니다.** 관찰 실험실에 Chrome / 외부 API / Mock / AI 끄기 선택과 기기별 상태를 추가했습니다. Chrome 선택 후 **이 기기에서 다운로드·활성화** 버튼으로 모델 준비를 시작합니다. 모드 선택만으로 다운로드나 추론을 시작하지 않습니다. 초기 기본값과 가져오기는 Mock/off를 유지합니다.

서버는 주민이 아는 사건만 영어 구조화 데이터로 준비합니다. Chrome이 제안한 목표·이유 코드·근거를 검증한 뒤 서버가 한국어 문구를 구성하고 원본 사건에 연결합니다. 자유로운 한국어 대화는 지원 범위가 아닙니다. 숨겨진 탭과 닫힌 탭은 실행을 중단하고, 재활성화에는 버튼 조작이 필요합니다. 기기 미지원·실패 시에도 세계는 진행하며 외부 API로 자동 전환하지 않습니다. 목표 요청·승인 결과·감사는 서버와 주고받습니다.

API 존재와 영어 가용성은 기기마다 확인합니다. **기기 진단 JSON 내보내기**에서 지원 상태와 최근 20회 실행의 입력량·처리 시간·결과 코드를 저장할 수 있습니다. 입력 한도 초과와 서버의 응답 거부는 구분하여 안내하고, 잘못된 응답이 반복되지 않도록 기기 실행을 중단합니다. 자동 검증과 실제 기기 시도는 [검증 기록](CHROME_AI_VALIDATION.md)에 구분했습니다. 상세 계약은 [개발 계획](CHROME_AI_PLAN.md)과 [LLM 아키텍처](LLM_ARCHITECTURE.md)를 참고하세요.

## Chrome 호출 분산 (v0.5.1)

같은 주민의 관련 사건을 모아 한 번의 목표 판단으로 처리합니다. 서버가 처음 60초 동안 사건을 모으고 실행 후 최소 60초 쉬며, 최근 60분간 6회·실제 UTC 하루 36회까지 실행합니다. 실패와 재할당도 예산에 포함합니다. 응답 없이 실행권이 끝나면 만료 뒤 60초 더 쉽니다. 새로고침·다른 기기·세계 초기화로 이 제한이 초기화되지 않습니다.

일상 행동은 일반 AI가 계속 처리합니다. 식량 부족이 해결됐거나 이미 가진 목표·완료된 시설이면 불필요한 추론을 생략합니다. 중요한 변화와 오래 기다린 주민을 고려해 처리하며, 서로 다른 주민의 사적 기억은 합치지 않습니다. 화면에는 사건 수집·휴식·시간당/일일 한도를 표시합니다.

목표·이유·근거를 함께 담은 허용 후보에서 목표 1개를 선택하도록 응답 제약을 좁혔습니다. 응답이 거부되면 화면과 진단 JSON에서 구체적인 사유를 확인할 수 있습니다. 기존 원문 없는 실패 기록의 사유를 소급 추정하지 않습니다.

v0.5.1 당시 자동 검증은 코어·서버 58개, 브라우저 16개였습니다. v0.6 검증 결과는 TASKS.md를 따릅니다. **2026-09-29 사용자 지시로 6A를 수용 완료 처리했습니다.** 새 실기기 자동 테스트 성공을 뜻하지 않습니다. 개발 환경의 정식 Chrome은 계속 `unavailable`이며, 앞선 사용자 Mac의 v0.5 성공 기록과 구분합니다. 업데이트 후에는 사이트를 새로고침하고 Chrome 활성화 버튼을 다시 눌러 주세요. 사건 수집과 예산으로 즉시 추론하지 않을 수 있습니다.

## 관찰하기

- **세계 관찰**: 지도 주민을 클릭하거나 ‘다음 주민’으로 선택합니다. 일상 탭에서 현재 행동과 판단 이유, 후보 Utility 점수, 욕구, 목표와 성격을 확인합니다.
- **관계 / 기억**: 근거를 클릭하면 실제 사건이 열립니다. 원인 사건과 이후 생긴 기억·관계·목표로 이동할 수 있습니다. 잊힌 기억의 원본 사건도 유지됩니다.
- **마을 경제**: 식량·생산/소비, 가격·거래량·임금, 재산 분포, 인구·도움·갈등의 실제 일별 그래프와 표를 확인합니다. 최근 90일을 그리고 모든 표본을 JSON으로 내보냅니다. 이전 버전에서 불러온 세계는 변환 시점부터 표본을 수집합니다.
- **생애 탭**: 선택 주민의 거래·임금·대여·상환·목표·관계를 날짜순으로 읽고, 원인 → 기억/소문 → 이후 선택의 근거를 연결된 타임라인으로 따라갑니다.
- **마을 주민**: 전체 주민을 목록으로 선택할 수 있습니다. 지도 조작 없이 키보드로도 접근할 수 있습니다.
- **세계의 기록**: 중요/사회/경제/전체 필터, 선택 주민 필터, 설명·사건 ID 검색과 이전 기록 보기를 지원합니다.
- **시간**: 일시정지, 한 틱(게임 내 10분), 1×/5×/20×. 1×는 실제 700ms당 한 틱입니다. 기기 모드는 숨겨진 탭에서 멈추며 서버 모드는 위 비접속 정책을 따릅니다.
- **관찰 실험실**: 3일 가뭄, 공동 식량 24개 투입, 시드 재시작, AI 방식 선택, 하루 관찰 진행. 개입은 사건 이력으로 남습니다.
- **기기 모드 저장**: 30초 간격 기기 자동 저장, 재접속 시 자동 복원, JSON 내보내기/가져오기. 초기화 전 세계는 별도 백업으로 유지하며 기기 공간 부족 시 파일로 내보냅니다. 장기 실행에서 localStorage 한도를 넘으면 JSON 파일 저장을 사용하세요.

시뮬레이션 코어는 브라우저 DOM, 타이머, 파일 시스템, 네트워크에 의존하지 않습니다. UI는 복제된 snapshot을 읽고 엔진 명령만 제출합니다.

## Headless

```bash
# 기본 12명, 100일, 중요 사건에서만 Mock 판단
npm run simulate -- --days 100 --seed 42

# LLM을 완전히 끄고 실행
npm run simulate -- --days 100 --seed 42 --llm off

# 상태 저장과 이어 실행 (--days는 추가 실행 일수)
npm run simulate -- --days 20 --seed 7 --save world.save.json
npm run simulate -- --days 80 --load world.save.json --save world.save.json

# 인구 압력 실험: 생산 기반은 같은 한 마을로 유지됨
npm run simulate -- --days 100 --seed 42 --npcs 100 --llm off
```

JSON 통계에는 실제 생존 인구·사망·평균 총 식량·창고 재고·공유·절도·갈등·양방향 관계·LLM 처리량이 포함됩니다. 출생·세대·정착지 통계도 실제 상태에서 계산합니다. 관계 순위 점수는 양방향 `(신뢰 + 애정 − 불만)`의 평균으로, 개별 관계 축의 0~100 범위와 다릅니다. `conflicts`는 절도 목격과 연체를 합한 사건 수입니다.

최신 장기 검증은 `npm run regression`으로 재실행합니다. 시드 7/42/123 × 100/365일 × 정상/초기 장기 가뭄/100명 다중 마을 조건의 18개 조합에서 자원 보존, 참조 무결성, 행동 정체, 중간 저장 후 이어 실행과 처음부터의 재현을 검사합니다. 별도로 100일 Mock 실행도 검증합니다. [검증 결과 해설](reports/README.md)과 실제 결과·사건 ID·사망 당시 조건·실행 시간·메모리 사용은 [reports/regression.json](reports/regression.json)에 있습니다. 수치는 게임 규칙 버전과 함께 해석해야 합니다.

시장과 주민의 코인은 거래/임금에서만 이동하며 새로 생성하지 않습니다. 수확 식량 중 1개를 시장에 납품할 때 시장 기금에서 최대 2코인을 지급하고, 기금이 없으면 납품/임금을 생략하고 수확물을 보유합니다. 주민 간 식량 거래는 판매자의 식량 3개를 남깁니다. 가격은 소유 식량 재고와 살아 있는 주민의 수요를 사용하며 식량 1~12코인, 하루 ±1코인으로 제한합니다. 대여는 자신의 식량 1개를 남기고 부분 상환할 수 있고, 연체 후에도 모두 갚으면 신뢰 일부가 회복됩니다.

농장 개선에는 실제 목재 8개가 들며 단계당 성장 배율이 0.35 증가합니다. 목수는 모델 없이도 농장을 개선합니다. 생산은 수확/채집한 물건을 기준으로 계산하고 미수확 자연 자원은 회계 재고에서 제외합니다. 공동 보관/매매/대여/공유/절도는 소유권 이동이며 생산이 아닙니다. 외부 식량 투입과 시설 투자 비용은 별도로 기록합니다.

## 한계와 확장 지점

초기 MVP는 한 마을을 운영했으며 현재 버전은 여러 정착지와 도시를 운영합니다. Food/Wood, 생산·소비·이동·수면·거래·대여·공유·절도·목격·소문, 6축 관계와 출처가 있는 기억을 구현했습니다. 기존 농장/창고/집 개선 외에 실제 토지의 신축과 도시 사업체를 지원합니다. 물은 우물에서 무한 공급되는 생존 요소이며 소지 자원은 아닙니다. 건강 악화는 결핍에서 발생하며 별도 전염병 모델은 없습니다. 계절은 3일마다 바뀌며 계절·날씨·토양·시설 내구도와 단계가 생산량에 영향을 줍니다.

서버 모델 어댑터를 구현했으며 실제 사용에는 모델 주소·이름과 필요한 인증 설정이 필요합니다. 배포 기본값은 Mock이며 모델 설정 전에도 관찰할 수 있습니다. 일반 Talk은 코어가 처리하고 모델의 말은 사용자가 명시 요청한 회상으로 기록합니다. 자연어의 사실성 자체를 자동으로 증명하지 않으므로 인용 원본과 함께 해석해야 합니다. 실제 모델 응답의 결정성을 가정하지 않고 **같은 시드 + 같은 명령/승인 응답 순서**를 재현성 계약으로 삼습니다.

기기/CLI 모드는 전체 사건을 메모리에 보존하며 저장 파일 150MB, 사건 100만 건까지 검증합니다. 서버 모드는 전체 사건을 D1에 분리 보관하고 엔진에 필요한 근거와 최근 사건만 체크포인트에 유지합니다. v0.8의 서버 세계 저장은 확정된 세계의 사건을 100건씩 스트리밍하며 브라우저 기본 다운로드로 저장합니다. 실행 체크포인트의 메모리 비용과 가져오기 한도는 유지되므로 무제한 이력 복원을 보장하지 않습니다. 가족·세대·여러 마을과 중요 사건 중심 기록은 v0.6에, 도시 확장은 v0.7에 추가했습니다. v0.8의 스트리밍 저장과 생태·역사·공동체 규칙은 HERITAGE.md를 따릅니다. 동물·전투·자유 건축, 근사 물리 LOD와 다중 서버 분산은 후속 확장입니다. 수백 명의 장기 실행은 서버의 이력 분리 방식을 사용합니다.

## 생활 다양성 확장 (v6)

성격 10축·욕망 6축·추가 신체 상태 4축, 26개 직업과 무직 상태, 기본 자원 14종·가공 상품 12종, 5종 주거를 시뮬레이션과 관측·주민 생성 화면에 적용했습니다. 생산·소비·임대료는 실제 재료와 코인에 연결되고 이전 저장 파일은 자동 변환됩니다. 수치와 제조법, 저장 정책은 [생활 다양성 설계](LIVING_SYSTEM_DESIGN.md)를 참고하세요.


## 주민의 매력과 관계

NPC 생성 화면에서 직업·나이·건강·외모·자산·성격을 설정하면 가장 두드러지는 매력 3가지가 표시됩니다. 성격을 바꾸면 미리보기도 바뀝니다. 같은 주민도 상대의 성격과 취향에 따라 다르게 받아들여집니다.

주민의 **관계** 탭에서 **서로 느끼는 인상**을 열면 항목별 양방향 점수와 이유를 볼 수 있습니다. 대화 상대 선택과 실제 만남 뒤 애정·신뢰·불만에 반영되며 당시 이유는 사건에 남습니다. 기존 세계에도 초기화 없이 적용되고 외부 AI는 필요하지 않습니다. 자세한 규칙은 [생활 다양성 설계](LIVING_SYSTEM_DESIGN.md)를 참고하세요.
