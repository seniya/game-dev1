# Project MicroVillage 개발 로드맵

## 1. 목적과 기준

이 문서는 [PROJECT.md](../PROJECT.md)의 승인된 명세를 실제 구현 작업으로 나눈 실행 계획이다. 프로젝트 목표나 수락 기준이 바뀌면 `PROJECT.md`를 우선 갱신하고, 그 변경을 반영해 이 문서를 갱신한다.

### MVP의 한 문장

플레이어가 20×20 타일 맵에 집과 작업장을 배치하면, 주민 한 명이 장애물을 피해 두 시설 사이를 자율적으로 왕복하는 브라우저 게임을 만든다.

### MVP 완료 기준

- 브라우저에서 20×20 격자 맵이 렌더링된다.
- 타일 호버와 선택 상태가 분명히 보인다.
- 집과 작업장을 유효한 타일에 배치할 수 있다.
- 주민 한 명이 구조물을 피해 집과 작업장 사이를 이동한다.
- 주민 상태(`IDLE`, `MOVING`, `WORKING`, `RESTING`)가 화면에 표시된다.

MVP에서는 자원 경제, 다수 주민, 저장/불러오기, 고급 UI를 구현하지 않는다. 이 기능들은 MVP가 위 기준을 모두 충족한 뒤에 시작한다.

## 2. 권장 구현 단위

각 작업 바퀴는 아래 항목 중 하나만 완료한다. 항목마다 실행 가능한 검증을 하고, 통과하면 커밋한 뒤 `STATUS.md`를 갱신한다.

| 순서 | 구현 단위 | 완료 확인 |
|---|---|---|
| 0 | 웹 앱 기반과 실행 명령 구성 | 빈 게임 화면을 브라우저에서 연다. |
| 1 | 캔버스, 20×20 그리드, 기본 카메라 | 모든 타일이 일정한 크기로 표시된다. |
| 2 | 화면 좌표와 타일 좌표 변환 | 마우스 위치와 선택 타일 좌표가 일치한다. |
| 3 | 타일 호버·선택 렌더링 | 호버와 선택이 서로 다른 시각으로 보인다. |
| 4 | 구조물 데이터와 배치 미리보기 | 집·작업장의 배치 가능/불가 상태가 보인다. |
| 5 | 구조물 배치와 충돌 맵 갱신 | 구조물 타일에는 중복 배치할 수 없다. |
| 6 | 주민 데이터와 직선 이동 | 주민 한 명이 목표 타일로 움직인다. |
| 7 | A* 경로 탐색과 장애물 회피 | 구조물을 피해 목표에 도달한다. |
| 8 | 주민 FSM과 집-작업장 왕복 | 상태 변화와 이동이 반복된다. |
| 9 | MVP 통합 검증과 사용자 안내 | MVP 완료 기준을 수동으로 모두 확인한다. |

## 3. 마일스톤 0: 개발 기반

### 목표

브라우저에서 빠르게 실행·검증할 수 있는 최소 웹 프로젝트를 만든다.

### 작업

1. 패키지 관리자와 개발 서버를 정하고 실행 명령을 문서화한다.
2. Canvas 기반 게임 화면과 기본 스타일을 만든다.
3. 테스트 가능한 모듈 경계를 정한다. 최소한 그리드, 경로 탐색, 시뮬레이션 상태는 렌더링 코드와 분리한다.
4. 코드 검사와 빌드 명령을 추가한다.

### 완료 조건

- 설치, 개발 서버 실행, 빌드 명령이 README 또는 개발 문서에 있다.
- 빈 게임 화면이 브라우저에서 열린다.
- 기본 검사와 빌드가 통과한다.

## 4. 마일스톤 1: 타일 맵과 입력

### 목표

20×20 직교 타일 맵을 그리고, 플레이어가 특정 타일을 정확히 가리키고 선택할 수 있게 한다.

### 작업

1. `GridMap` 모델에 지형, 구조물 점유, 통행 비용을 분리해 저장한다.
2. 타일 렌더러로 잔디 등 기본 지형을 렌더링한다.
3. 화면·월드·그리드 좌표 변환 함수를 작성하고 단위 테스트한다.
4. 마우스 호버, 클릭 선택, 선택 타일 표시를 만든다.
5. 필요하면 먼저 드래그 이동과 휠 줌을 추가하되, 기본 타일 선택을 깨뜨리지 않아야 한다.

### 완료 조건

- 20×20 타일의 경계가 명확하고 프레임이 안정적이다.
- 화면 어디를 클릭해도 선택 좌표가 올바르다.
- 호버와 선택 상태가 동시에 이해 가능하게 보인다.

## 5. 마일스톤 2: 건설과 공간 점유

### 목표

플레이어가 집과 작업장을 배치하고, 그 결과가 이동 가능한 공간에 즉시 반영되게 한다.

### 작업

1. `BuildingDefinition`에 종류, 풋프린트, 입구, 비용을 정의한다. MVP에서는 1×1 집과 1×1 작업장부터 시작한다.
2. 건설 도구 UI에서 집·작업장을 선택한다.
3. 배치 미리보기와 유효/무효 색상을 렌더링한다.
4. 지형 통과 가능 여부, 구조물 중복, 입구의 인접 보행 가능 타일을 검사한다.
5. 배치 확정 시 `Structure Layer`와 `Nav Cost Layer`를 함께 갱신한다.

### 완료 조건

- 유효한 빈 타일에는 구조물을 배치할 수 있다.
- 구조물 위 또는 입구가 막힌 곳에는 배치할 수 없다.
- 새 구조물이 지도와 통행 데이터에 즉시 반영된다.

## 6. 마일스톤 3: 주민 이동과 자율 상태

### 목표

주민 한 명이 게임 논리 틱에 따라 집과 작업장 사이를 장애물 없이 왕복한다.

### 작업

1. 렌더링과 분리된 고정 논리 틱(20 TPS)을 만든다.
2. `Villager`에 타일 위치, 이전 위치, 목표, 경로, 상태를 둔다.
3. `Nav Cost Layer`를 입력으로 하는 A* 경로 탐색을 구현하고 단위 테스트한다.
4. 렌더 루프에서 이전·현재 위치를 보간해 주민을 부드럽게 표시한다.
5. `IDLE → MOVING → WORKING → MOVING → RESTING` 상태 전이를 만든다.
6. 집 또는 작업장이 없거나 경로가 없을 때는 안전하게 `IDLE`로 남긴다.

### 완료 조건

- 주민이 구조물을 통과하지 않는다.
- 집과 작업장을 배치하면 주민이 두 입구 사이를 반복 이동한다.
- 이동, 작업, 휴식 상태가 화면에서 확인된다.
- 브라우저 프레임률 변화가 논리 속도를 바꾸지 않는다.

## 7. 마일스톤 4: MVP 통합 검증

### 목표

기능을 한 화면에서 반복 실행해도 안정적인 최초 플레이 가능 프로토타입을 만든다.

### 검증 시나리오

1. 새 게임을 열고 20×20 격자 맵이 표시되는지 확인한다.
2. 여러 타일을 호버·선택해 좌표와 강조 표시를 확인한다.
3. 집과 작업장을 서로 떨어진 곳에 배치한다.
4. 주민이 두 구조물을 피해 목적지까지 이동하는지 확인한다.
5. 주민 상태가 `IDLE`, `MOVING`, `WORKING`, `RESTING`으로 전이되는지 확인한다.
6. 구조물 배치를 추가해 경로가 달라져도 주민이 멈추거나 구조물을 통과하지 않는지 확인한다.
7. 코드 검사·테스트·프로덕션 빌드를 실행한다.

### 완료 조건

- MVP 완료 기준을 모두 통과한다.
- 알려진 제한 사항과 다음 우선순위를 `STATUS.md`에 기록한다.
- 검증 통과 상태를 커밋으로 남긴다.

## 8. MVP 이후 확장 순서

| 단계 | 추가 범위 | 시작 조건 |
|---|---|---|
| 5 | 다중 타일 구조물, 입구 검증 고도화, 도로, 철거 | MVP 이동·배치가 안정적이다. |
| 6 | 다수 주민, 욕구, 침대·직업 배정, 시간 분할 경로 탐색 | 단일 주민 FSM이 검증됐다. |
| 7 | 나무·바위 채집, 창고, 운반, 건설 자원 운반 | 주민 예약과 경로 시스템이 안정적이다. |
| 8 | HUD, 시간 배속, 인스펙터, 건설 메뉴 | 핵심 시뮬레이션 데이터를 화면에 노출할 준비가 됐다. |
| 9 | 가공 생산 체인, 저장/불러오기, 밸런싱, 사운드·애니메이션 | 물류 순환이 한 번 완성됐다. |

## 9. 기술 원칙과 위험 관리

- 논리 시뮬레이션은 20 TPS 고정 틱으로, 렌더링은 `requestAnimationFrame`으로 분리한다.
- 지형·구조물·자원·이동 비용은 독립 레이어로 저장한다.
- 경로 탐색 결과는 구조물 변경 시 무효화하며, 다수 주민 단계부터는 틱당 계산 수를 제한한다.
- 자원과 작업 대상은 이후 단계에서 예약 처리해 중복 대상 선택을 막는다.
- 각 게임 객체는 JSON 직렬화 가능한 데이터 구조를 유지해 저장/불러오기 확장에 대비한다.
