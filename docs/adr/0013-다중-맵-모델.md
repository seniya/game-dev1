# ADR 0013 — 다중 맵 모델: 맵은 여럿, 마을은 하나

- **상태**: 확정
- **일자**: 2026-09-02
- **관련 문서**: `docs/plan/roadmap_03.md` Phase 2, ADR 0003(지형 자료구조), ADR 0005(구역), ADR 0008(저장)
- **구현**: `src/core/maps.ts`, `src/core/terrainGen.ts`(`generateCave`), `src/sim/Game.ts`, `src/core/save.ts`

## 배경

ADR 0003은 높이맵을 고르면서 **"동굴은 별도 맵으로 다룬다"**를 전제로 달아 뒀다. 높이맵은
오버행과 천장을 표현할 수 없으므로 동굴을 지형 지물로 만들 수 없기 때문이다. 그 전제를
실제로 쓰려면 게임이 맵을 여럿 들 수 있어야 하는데, `Game`은 `terrain`과 `resources`를
각각 하나씩 `readonly` 필드로 들고 있었고 저장 형식도 지형 한 벌만 담았다.

로드맵 03은 **구조를 먼저 열고 콘텐츠를 나중에 넣는다**로 순서를 잡았다. 이 ADR은 그 구조다.

## 결정

### 1. 맵은 `Game` 안의 목록이고, 지금 있는 맵이 하나 있다

```
maps: Map<MapId, { terrain, resources, portal }>
current: MapId
```

`game.terrain`과 `game.resources`는 **지금 있는 맵을 가리키는 게터**가 됐다. 필드에서
게터로 바뀌었을 뿐이라 렌더러·피킹·규칙의 호출부는 그대로다. 맵을 늘리는 일이 기존 코드를
휘젓지 않는다는 것이 이 형태를 고른 이유다.

### 2. 마을은 지상에만 있다

건물·주민·요청·창고는 지상 지형에 묶인 채로 둔다. 맵 속성 하나(`isVillageMap`)로 규칙을
가른다 — "이 맵에 마을이 있는가"만 물으면 되므로 맵이 늘어도 조건문이 늘지 않는다.

동굴에서 달라지는 것:

| 규칙 | 동굴에서 |
|---|---|
| 건축·철거·미리보기 | 거부(`notVillage`) |
| 창고 접근 | 닿지 않음 |
| 건물 점유 판정 | 없음(지상 좌표가 동굴 칸을 막지 않는다) |
| 구역 잠금 | 없음 — 구역은 마을 중심에서의 거리다(ADR 0005) |
| 주민·건물 렌더링 | 그리지 않음 |

**마을의 시간은 계속 흐른다.** 동굴에 있는 동안 건축이 멈추고 주민이 얼어붙으면 "오래
있을수록 손해"라는 규칙이 생긴다. 자원 리스폰도 모든 맵에서 함께 흐른다.

### 3. 동굴은 벽이 꽉 찬 기둥, 바닥이 한 칸

높이맵으로 천장을 만들 수 없으므로 동굴을 **위에서 내려다본 통로**로 그린다. 벽은 최대
높이(5)까지 채운 암반이고 파낸 자리는 높이 1이다. 등반 한계가 1칸이므로(ADR 0004) 벽은
따로 규칙을 두지 않아도 통행을 막는다. **자료구조를 바꾸지 않고 동굴이 된다.**

생성은 방을 몇 개 파고 **직전 방과 L자 통로로 잇는** 방식이다. 노이즈로 뚫으면 닿을 수 없는
방이 생기는데, 이어 붙이며 파면 연결이 생성 방식에서 보장된다 — 나중에 길찾기로 검사할
필요가 없다. 테스트는 그 성질을 너비 우선 탐색으로 고정한다.

### 4. 통로는 지형에서 파생되고, 저장하지 않는다

- **지상 입구**: 마을 중심에서 가장 먼 칸. 구역이 거리로 나뉘므로(ADR 0005) 가장 먼 칸은
  곧 산악이고, "동굴은 산악 너머"라는 기획서 5.2의 순서가 별도 규칙 없이 지켜진다.
  같은 거리라면 걸어 들어갈 길이 많은 칸을 고른다 — 구석은 이웃이 둘뿐이라 답답하다.
- **동굴 출구**: 파낸 칸 중 중앙에 가장 가까운 것. 방 한가운데라 사방으로 길이 열린다.

둘 다 지형만 있으면 다시 계산되므로 저장하지 않는다. 파생값을 저장하면 저장과 파생이
어긋난 상태가 생긴다(로드맵 02 Phase 1의 원칙).

### 5. 맵은 처음 갈 때 시드에서 만들어진다

동굴은 **처음 들어갈 때** 생성된다. 가 보지 않은 맵을 들고 있을 이유가 없고, 단위 테스트가
작은 지형 하나만으로 게임을 세울 수 있어야 하기 때문이다. 저장에도 다녀온 맵만 담긴다.

맵 시드는 세계 시드에 맵 종류를 섞어 만든다(`mapSeed`). 같은 시드로 두 맵을 만들면 동굴이
지상과 같은 모양이 되고, 섞지 않으면 세계마다 같은 동굴이 나온다.

## 검토한 대안

- **맵마다 `Game`을 하나씩 두고 갈아 끼운다**: 맵 사이에 공유되는 것(인벤토리·마을·레벨)을
  어디에 둘지가 곧바로 문제가 된다. 결국 그것들을 담을 상위 객체가 필요해지므로 지금 형태와
  같아진다. 제외.
- **동굴을 지형 지물로 만든다(오버행 허용)**: ADR 0003이 이미 검토하고 제외한 길이다.
  복셀 배열로 바꾸면 메모리가 5배가 되고 평탄도 판정이 "표면 높이"를 새로 정의해야 한다.
- **떠난 맵을 버리고 시드에서 다시 만든다**: 메모리는 아끼지만 파고 쌓은 변경분을 잃는다.
  변경분을 저장해야 하는 이상 들고 있는 편이 단순하다.
- **통로를 고정 좌표에 둔다**: 맵 크기와 지형에 따라 벽 속이나 물가에 놓일 수 있다.

## 예상되는 결과

**얻는 것**

- 콘텐츠를 넣을 자리가 열렸다. 로드맵 03 Phase 3(희귀 광물·어둠)은 이제 규칙과 표현만
  더하면 되고, 구조를 다시 건드리지 않는다.
- 저장이 맵 배열이 되어 맵을 더 늘릴 때 형식을 또 바꾸지 않아도 된다.

**감수하는 것**

- 메모리가 맵 수에 비례한다. 32×32 맵 하나가 `Uint8Array` 두 개(약 6KB)라 지금 규모에서는
  문제가 아니지만, 맵이 늘면 다시 볼 값이다.
- 동굴은 아직 **비어 있다.** 자원도 어둠도 없다 — Phase 3의 몫이다. 지금 들어가는 것은
  구조가 동작한다는 확인이지 콘텐츠가 아니다.
- 지상 입구가 맵 가장자리에 놓인다. 테스트로 "걸어갈 수 있음"은 고정했지만, 지형 생성이
  크게 바뀌면 다시 확인해야 한다.
