# ADR 0022 — 캐릭터 보행을 이동 상태에서 파생한다

- **일자**: 2026-09-04
- **상태**: 채택

## 배경

플레이어와 주민은 현재 한 장의 정적 말 스프라이트로 그려지고, 타일 간 위치가 선형으로
보간된다. 그래서 실제 이동 규칙은 명확해도 화면에서는 발을 옮기지 않고 미끄러지는 것처럼
보인다. 캐릭터는 화면에서 가장 자주 움직이는 요소라 이 인상이 마을의 완성도를 크게 낮춘다.

## 결정

현재 이동의 **방향과 0~1 진행도**를 렌더용 pose에 포함한다. 위치에는 smoothstep 가감속을
적용하고, 절차적 캐릭터 스프라이트는 이 진행도로 다리·팔·몸통 높이가 다른 보행 포즈를
선택한다. 방향은 머리의 시선·앞팔 위치에만 쓴다.

이 값들은 이동 상태에서 매 프레임 계산하는 파생값이므로 저장하지 않는다. 이동 중 저장한
게임을 다시 열면 기존 정책대로 정지 상태가 된다. 스프라이트를 만들 수 없는 환경은 같은
입력을 도형 폴백에 적용한다.

## 검토한 대안

1. **선형 이동은 두고 정적 그림만 자세히 그린다**: 실루엣은 나아지지만 미끄러지는 핵심
   인상이 남는다.
2. **시간 기반 전역 애니메이션 타이머를 둔다**: 서 있는 사람도 계속 흔들 수 있지만,
   렌더 시간과 시뮬레이션 시간이 갈리고 테스트·재현성이 나빠진다.
3. **스켈레탈 애니메이션 또는 외부 스프라이트 시트를 도입한다**: 풍부한 동작은 가능하지만
   작은 타일 게임에 비해 자산 파이프라인과 의존성이 과하다. ADR 0009의 코드 생성 정책도
   약해진다.
4. **논리 이동 자체를 물리 이동으로 바꾼다**: 느낌은 달라질 수 있으나 충돌, 입력, 저장,
   통과 플레이의 규칙을 넓게 건드린다.

## 예상되는 결과

- 이동 시작과 끝이 부드러워지고, 캐릭터가 발을 옮기는 방향이 읽힌다.
- 논리 좌표·충돌·저장 형식은 변하지 않아 기존 게임 규칙과 자동 플레이 측정이 유지된다.
- 포즈가 진행도의 순수 함수가 되어 단위 테스트와 헤드리스 폴백을 유지할 수 있다.
- 정교한 개별 행동 애니메이션은 제공하지 않는다. 필요한 경우 실제 플레이 관찰 뒤 별도
  결정으로 확장한다.
