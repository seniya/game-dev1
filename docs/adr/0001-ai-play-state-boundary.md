# ADR 0001 — AI의 제안과 놀이의 상태·판정을 분리한다

- 날짜: 2026-09-28
- 상태: 제안 — 프로젝트 후보 선택과 첫 실험 후 채택 여부 결정

## 배경

AI 놀이 사례에는 자유로운 반응과 예상하지 못한 결과를 즐기는 경험이 있다.
동시에 존재하지 않는 증거, 반복 대사, 지시가 반영되지 않는 행동은 플레이를 방해한다.
공개 사례와 검토 근거는 [조사 문서](../research/2026-09-28-ai-play-opportunities.md)에 있다.

## 결정 제안

- AI는 자연어 해석, 캐릭터 표현, 콘텐츠·전술 후보 생성에 사용한다.
- 상태 변경, 자원, 증거, 점수, 승패는 검증 가능한 게임 규칙으로 관리한다.
- 전략 놀이의 첫 실험은 제한된 전술 표현을 사용한다. 생성된 임의 코드를 바로 실행하지 않는다.
- 모델 호출은 사용자 개입과 의미 있는 사건에 맞추고, 매 프레임 호출하는 구조는 피한다.
- 재현에는 초기 상태와 난수 시드뿐 아니라 모델이 제안하고 실제 적용된 행동 기록도 저장한다.
- 대기·실패가 발생했을 때에는 진행 상태를 보여주고 검증된 기본 행동으로 복구한다.
- 모델 제공자와 프레임워크는 지금 선정하지 않는다.

## 검토한 대안

1. AI가 세계 상태와 판정까지 모두 작성한다: 시작은 빠르지만 모순과 불공정한 판정을 추적하기 어렵다.
2. 모든 행동을 수작업 분기로 작성한다: 예측 가능하지만 자유로운 언어 입력의 효용을 시험하기 어렵다.
3. AI가 실행할 코드를 생성한다: 표현력이 높지만 초기 놀이 검증에 비해 실행 격리와 디버깅 부담이 크다.

## 예상되는 결과

- 행동과 승패의 근거를 보여주고 재현·테스트할 수 있다.
- API 지연과 비용을 경기 속도에서 분리할 여지가 생긴다.
- 표현 범위가 제한되므로 자연어가 버튼 선택보다 편하고 재미있는지 반드시 비교해야 한다.
- 이 원칙은 게임형 후보에 대한 제안이다. 음악·코미디 파티에서 사람이 투표하는 구조는 별도로 설계한다.

## 채택 시 필요한 검증

- 허용되지 않은 행동, 없는 대상, 범위를 벗어난 수치를 거부한다.
- 모델 응답 실패나 시간 초과에도 게임 상태가 손상되지 않는다.
- 같은 초기 상태와 적용 행동 기록으로 같은 경기 결과를 재생한다.
- 추리 후보라면 증거와 인물별 지식 범위의 일관성을 검증한다.
- 구현한 함수에는 주석을 작성하고, 기능 구현 후 해당 동작의 테스트를 작성한다.
