# ADR 0023 — 새 건물 크기는 저장하고, 방향키는 이동에 쓴다

- **일자**: 2026-09-04
- **상태**: 채택

## 배경

마을과 건물이 작아 성장한 마을의 밀도·건축 감상이 약하다. 지도·외형·설계도 규모는
앞으로도 조정 대상인데, 블루프린트에서 파생되던 기존 건물 크기를 그대로 바꾸면 이미
저장된 마을의 점유 칸, 주민의 집 출입, 창고 접근이 조용히 바뀔 수 있다.

또한 화살표 키는 대부분의 게임에서 이동으로 예상하지만 현재는 겨냥이다. 단순히 바꾸면
마우스 없는 사용자가 대상 칸을 고를 방법을 잃는다.

## 결정

새로 배치하는 건물에는 현재 블루프린트의 `width`·`depth`를 저장한다. 저장에 이 선택적
필드가 없는 과거 건물은 이전 풋프린트 표로 읽는다. 모든 점유·출입·렌더링은 건물 인스턴스가
가진 크기를 기준으로 한다. 이번 변경은 지도 확대·기본 확대율·건축 외형을 먼저 적용하고,
실제 풋프린트 증가는 통과 플레이와 배치 규칙을 함께 재설계할 때 별도 단계로 한다.

방향키와 WASD는 모두 이동으로 받는다. 겨냥은 IJKL로 옮기며, 마우스 겨냥과 Space 행동은
변하지 않는다. 도움말과 상황 안내도 새 경로를 표기한다.

## 검토한 대안

1. **블루프린트 크기만 일괄 변경**: 구현은 짧지만 기존 저장 마을의 충돌과 주민 이동을
   깨뜨리고, 자동 배치·통과 플레이의 공간 가정도 한꺼번에 무너뜨린다.
2. **건물 크기는 유지하고 그림만 크게 그림**: 배치·충돌 영역과 외형이 달라져 건물이
   서로 겹쳐 보인다.
3. **방향키를 겨냥으로 유지**: 기존 사용자는 익숙하지만 새 사용자의 기본 기대를 거스른다.
4. **방향키 이동만 넣고 키보드 겨냥을 제거**: 키보드 전용 플레이 원칙(ADR 0012)을 위반한다.

## 예상되는 결과

- 새 마을은 더 넓은 공간과 가까운 기본 시야에서 역할이 읽히는 건물을 짓는다.
- 기존 저장은 기존 건물 크기를 유지해 점유·접근·주민 규칙이 보존된다.
- 새 사용자는 방향키로 즉시 걸을 수 있고, 키보드 전용 사용자는 IJKL로 모든 대상 행동을
  계속 수행한다.
- 건물 크기가 저장 형식의 선택적 필드가 되므로 형식 버전은 올리지 않는다.
