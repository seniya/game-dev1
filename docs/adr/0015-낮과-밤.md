# ADR 0015 — 낮과 밤: 시각은 파생값, 어둠은 두 종류

- **상태**: 확정
- **일자**: 2026-09-02
- **관련 문서**: `docs/plan/roadmap_03.md` Phase 4, `docs/plan/project.md` 8절, ADR 0011, ADR 0014
- **구현**: `src/core/daycycle.ts`, `src/sim/Game.ts`, `src/render/WorldRenderer.ts`, `src/ui/VillageHud.ts`

## 배경

기획서 8절은 낮밤 사이클을 **MVP 제외 항목**으로 뒀다. 로드맵 03이 이것을 넣는 이유는
분위기 때문이 아니라 **뒤따르는 두 Phase의 전제**이기 때문이다 — 기획서 5.4의 NPC는
"정해진 시간대에 배회"하고, 9절의 몬스터 침입은 밤에 오는 것이 자연스럽다. 시간축이 없으면
둘 다 어색한 형태가 된다.

로드맵은 이 Phase에서 "저장에 시각을 포함한다"고 적어 뒀고, 0절은 그것을 **형식이 바뀌는
세 번 중 두 번째**로 셌다.

## 결정

### 1. 시각은 저장하지 않는다 — 누적 시간에서 파생된다

로드맵의 예상과 달리 **저장 형식을 바꾸지 않았다.** 누적 시뮬레이션 시간(`elapsedMs`)이
이미 저장되고 있으므로, 시각은 그 값에서 계산하면 된다.

ADR 0011이 배수형 보너스를 두고 내린 판단과 같은 규칙이다 — **다른 값에서 유일하게 결정되는
것은 저장하지 않는다.** 저장하면 저장값과 파생값이 어긋난 상태를 만들 수 있고, 마이그레이션
부담도 는다(ADR 0008 개정).

### 2. 하루는 4분, 아침에 시작한다

| 값 | 결정 | 근거 |
|---|---|---|
| 하루 길이 | 4분(게임 시간) | 봇 통과 플레이 4.9분에 **2일**이 흐른다. 봇 5분은 사람 40~60분이므로 사람 기준 하루가 약 4분이고, 첫 세션에 열 번 남짓 해가 뜨고 진다 |
| 시작 시각 | 07:40 무렵 | 어두운 화면으로 시작하면 처음 켠 사람이 할 일을 찾기 어렵다. 정오에 시작하면 첫 밤이 너무 빨리 온다 |
| 구간 비율 | 낮 42% · 밤 38% · 전환 20% | 밤에는 시야가 좁아 채집이 불편하다. 밤이 길면 **기다리는 시간**이 된다 |

이 숫자는 통과 플레이 테스트가 지킨다 — 한 판에 2~10일이 흐르지 않으면 실패한다.

### 3. 어둠은 두 종류이고, 서로 다른 것이다

| | 동굴의 어둠(ADR 0014) | 밤의 어둠 |
|---|---|---|
| 성격 | 장소 | 시간 |
| 밝은 반경 | 5칸 | 8칸 |
| 최대 세기 | 0.8 | 0.45 × 밤의 정도 |
| 색조 | 없음 | 밤의 푸른색 + 전환의 노을 |

**동굴 안에서는 시간대 색조를 얹지 않는다.** 하늘이 보이지 않는 곳이다. 밤의 시야를 동굴보다
넓고 옅게 둔 이유는 마을을 돌아다니는 것이 막히면 안 되기 때문이다 — 밤은 불편함이지 벌칙이
아니다.

전환은 **이어 붙인다.** 해가 툭 꺼지면 사이클이 사건처럼 보이는데, 이 게임에서 낮밤은
사건이 아니라 배경이다. 노을은 전환의 한가운데에서 가장 짙다 — 해가 지평선에 걸린 순간이
가장 붉다.

### 4. 렌더러는 "밤"도 "동굴"도 모른다

`Game.atmosphere()`가 색조와 빛의 중심·반경·세기를 값으로 돌려주고, 렌더러는 그것을 그린다.
어디가 왜 어두운지는 규칙의 몫이다. 덕분에 두 어둠이 같은 코드로 그려지고, 규칙만 보고
"밤에 동굴에 있으면 어떻게 되는가"를 답할 수 있다(동굴의 어둠만 적용된다).

## 검토한 대안

- **시각을 저장 형식에 넣는다**: 로드맵의 원래 계획이었다. 누적 시간이 이미 저장된다는 것을
  확인하고 그만뒀다. 형식을 바꾸는 일은 마이그레이션 부담을 늘리므로 피할 수 있으면 피한다.
- **낮밤을 계단으로 끊는다**: 구현이 단순하지만 해가 툭 꺼진다. 제외.
- **밤에 채집 속도를 낮추거나 자원을 막는다**: 시간에 규칙을 얹으면 사이클이 진행 압박이
  된다. 캐주얼 타운 빌더에서 "밤이 되기 전에 서둘러라"는 성격이 맞지 않는다. 지금 밤이
  바꾸는 것은 **보이는 범위뿐**이다. 규칙을 얹는 것은 Phase 5(직업 시간대)와 Phase 6(침입)의
  몫이며, 그때는 그것이 콘텐츠다.
- **날씨와 계절**: 로드맵 03이 범위 밖으로 뒀다. 낮밤과 달리 그것을 필요로 하는 시스템이 없다.

## 예상되는 결과

**얻는 것**

- 시간축이 생겨 Phase 5(직업의 시간대)와 Phase 6(야간 침입)이 얹힐 자리가 마련됐다.
- 화면이 시간에 따라 변한다. 저장 형식은 그대로다.
- 두 종류의 어둠이 한 경로로 그려진다.

**감수하는 것**

- 밤이 **아직 아무것도 바꾸지 않는다.** 보이는 범위만 좁아질 뿐, 할 일은 낮과 같다.
  그것을 채우는 것이 Phase 5·6이다. 그때까지 밤은 분위기다.
- 하루 4분은 봇 측정에 기댄 추정이다. 사람이 실제로 어떻게 느끼는지는 확인하지 못했다.
- 시각이 누적 시간에서 파생되므로, 언젠가 "시간을 건너뛰는" 기능(잠자기 등)을 넣으려면
  누적 시간 자체를 밀어야 한다. 지금 구조에서는 그것이 자연스러운 방식이다.
