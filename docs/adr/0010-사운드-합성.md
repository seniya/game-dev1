# ADR 0010 — 소리를 파일 대신 합성한다

- **상태**: 확정
- **일자**: 2026-09-02
- **관련 문서**: `docs/plan/roadmap_02.md` Phase 3, ADR 0009
- **구현**: `src/audio/sounds.ts`, `src/audio/AudioPlayer.ts`

## 배경

로드맵 02는 "사운드 리소스 조달"을 Phase 3 착수 전 결정 사항으로 남겼다. 아트와 같은
문제다 — 음원 파일을 가져올 수 없다. 그리고 아트에서 이미 같은 문제를 **생성**으로
풀었다(ADR 0009).

## 결정

**Web Audio의 오실레이터와 노이즈로 소리를 합성한다.** 음원 파일을 쓰지 않는다.

소리는 `SOUND_RECIPES`에 "무엇으로 만드는가"만 적어 두고, `AudioPlayer`가 그대로 만든다.

| 종류 | 만드는 법 |
|---|---|
| 타격음(파기·벌목·채굴) | 백색 소음 + 저역 통과 필터 + 급한 감쇠 |
| 알림음(완공·이주·레벨업) | 짧은 톤을 이어 붙인 음계 |
| 거절음 | 낮은 톱니파 한 음 |
| 배경음 | 5음 음계에서 고른 음을 길게 늘여 이어 냄 |

**재질은 필터 주파수로 나눈다.** 흙은 700Hz, 나무는 1400Hz, 돌은 2600Hz로 걸어 같은
노이즈에서 서로 다른 재질감이 난다. 이것이 파일 없이도 소리를 구분되게 만드는 핵심이다.

### 배경음은 루프가 아니라 생성

고정 루프 파일 대신 5음 음계에서 음을 하나씩 골라 2.6초씩 늘인다. 같은 구간이 반복되지
않아 오래 들어도 덜 지겹고, 파일도 필요 없다. 볼륨은 효과음의 8분의 1 수준으로 낮춰
조작음이 묻히지 않게 했다.

### 첫 사용자 입력에서 오디오를 켠다

**브라우저는 사용자 입력이 있기 전에 오디오를 켜 주지 않는다.** 그래서 `AudioContext`를
생성자에서 만들지 않고 `unlock()`에서 만들며, 클릭·키 입력 처리 첫머리에서 부른다.
그전의 재생 요청은 조용히 무시한다 — **소리가 안 나는 것보다 예외로 게임이 죽는 것이 나쁘다.**

탭을 옮겼다 돌아오면 컨텍스트가 정지 상태로 남을 수 있으므로 `unlock()`이 `resume()`도 겸한다.

잠금을 푼 직후 배경음 첫 음은 1.2초 미룬다. 잠금을 푼 것은 사용자가 무언가를 눌렀다는
뜻이고, 그 조작음과 배경음이 겹치면 둘 다 뭉개진다.

### 볼륨은 단계 버튼

슬라이더 대신 4단계(끔/낮음/보통/큼)를 돌리는 버튼 하나다. 조작이 단순하고, 지금 어느
단계인지 글자(`소리 ●●○`)로 보인다. 설정은 **게임 저장과 다른 키**에 담는다 —
"새로 시작"으로 마을을 지워도 볼륨은 남아야 하고, 저장 형식 버전이 올라도 설정까지 버릴
이유가 없다.

### 규칙은 소리를 모른다

`Game`은 사건에 `cue`(`migration`, `levelUp`, `buildDone` 등)만 붙여 알린다. 그것을 문구로
쓸지 소리로 쓸지 연출로 쓸지는 UI가 정한다. Phase 7에서 만든 알림 통로를 그대로 재사용한
것이며, 덕분에 규칙 테스트에 오디오가 끼어들지 않는다.

## 검토한 대안

- **음원 파일(mp3/ogg)**: 표현의 상한이 높다. 그러나 조달이 선행 과제이고, 파일 용량과
  로딩 실패 처리가 새로 들어온다. 아트와 같은 이유로 제외했다. 나중에 파일을 쓰기로 하면
  `AudioPlayer.play`의 내부만 바꾸면 된다 — `SoundId`가 이미 경계다.
- **오디오 라이브러리(Howler 등)**: 런타임 의존성 0개를 깨고, 우리가 쓰는 기능은 Web Audio
  기본 API로 충분하다.
- **배경음 없이 효과음만**: 조용한 편이 방해가 적지만, 마을 건설 게임에서 완전한 무음은
  허전하다. 낮은 볼륨의 생성 배경음이 절충이다.

## 예상되는 결과

**얻는 것**: 파일 없이 행동에 반응이 생긴다. 타격·완공·이주·레벨업이 귀로도 전달된다.
런타임 의존성 0개가 유지된다.

**감수하는 것**:
- 합성음이라 "게임 사운드"다운 두께가 없다. 타격음은 노이즈 버스트라 재질 구분은 되지만
  질감이 단순하다.
- 소리를 고치려면 코드를 고쳐야 한다.
- 브라우저마다 Web Audio 구현 차이가 있어 음색이 조금씩 다를 수 있다.
