# 작업 상태 — 로드맵 05 Phase 1~4 완료 (0·5는 사용자 몫)

- **일자**: 2026-09-02
- **확인 방법**: 헤드리스 크롬(CDP)으로 키보드와 **실제 마우스 클릭**까지 직접 확인.
  스크린샷 50장째.
- **직전 상황**: Phase 6(지붕 없는 건물)을 먼저 마친 뒤 나머지를 진행하라는 요청.

## Phase 1 — 마우스로도 끝까지

키보드는 로드맵 03에서 완결했지만 **마우스 쪽이 비어 있었다.** 마우스만 쥔 사람은 무엇을
지을지 고를 수 없었다 — 로드맵 03 Phase 1이 고친 결함과 같은 것이 반대편에 남아 있었다.

- 건축 패널의 줄을 눌러 설계도를 고른다(숫자 키의 아홉 상한도 없다)
- 낼 수 있는 요청 아이콘을 눌러 납품한다. 낼 수 없는 것은 눌리지 않는다
- 도구 표시를 눌러 넘긴다
- 도움말에 늘 보이는 버튼을 뒀다

**화면에서만 잡힌 것**: 도구 버튼이 반응하지 않았다. CSS가 `.bar__tool, .bar__storage`로
묶여 있어 내가 넣은 규칙이 들어가지 않았고, computed `pointer-events`가 none이었다.

## Phase 2 — 첫 30분 다듬기

첫 배치의 마찰은 자리 부족이 아니었다. 시작 반경 3칸 안에도 20~34곳이 있는데
**어디가 되는지 보이지 않는 것**이 문제였다.

- 건축 모드에서 놓을 수 있는 자리를 옅은 초록으로 표시(플레이어 주변 여덟 칸)
- 자리가 있으면 "초록 표시가 있는 자리에", 없으면 "삽으로 파거나 흙을 쌓아 고르세요"
- 거절 문구도 방법을 알린다 — "삽을 들고 Space로 파거나 Q로 흙을 쌓으세요"

알려 주는 것까지가 안내이고 자동으로 놓아 주는 것은 게임을 없애는 일이라, 자리만 보여준다.

## Phase 3 — 무슨 일이 있었는지 남기기

- 이정표 아홉(첫 채집·예치·착공·주민·요청·일터·동굴·침입·수리)과 레벨 도달 시각
- 거절 사유별 횟수 — "어디서 멈췄는가"를 가장 잘 말해 준다
- 저장 메뉴의 "기록 복사". 클립보드가 막혀도 얻을 수 있게 **화면에도 띄운다**
- 담는 것은 시각·사건·횟수뿐. 서버로 보내지 않는다

**기록이 곧바로 값을 했다.** 확인용 스크립트가 잠긴 구역을 여덟 번 때린 것이 그대로 남아,
왜 "첫 채집: 없음"인지 설명해 줬다.

**같은 확인에서 회귀를 찾았다.** 소리 버튼이 로드맵 03 Phase 1 이후로 아무 일도 하지
않고 있었다 — 입력 연결을 `InputRouter`로 옮길 때 `setVolumeHandler` 호출이 함께 지워졌다.
테스트도 화면 확인도 잡지 못한 종류다(버튼은 그려지고 눌리기만 했다). 되살렸다.

## Phase 4 — 깊이 하나: 일터에 닿아야 일한다 (ADR 0021)

셋(몬스터 길찾기 · 동굴 깊이 · 일터 도착) 중 **보이는 것과 규칙이 어긋난 곳**을 골랐다.
지붕을 걷어낸 뒤로 마을 밖을 걷는 사람이 창고에 목재를 넣고 있었다.

- 일터 점유 영역과 한 칸 옆까지가 "일터에 있다"
- 닿지 못한 동안 진행도는 멈출 뿐 되돌아가지 않는다
- 경로 탐색은 넣지 않는다 — 문 앞 규칙(ADR 0018)이 이미 건물을 고립시키지 않는다
- **재 보니 열두 칸 출퇴근에 40초**가 걸려 하루의 절반을 길에서 보냈다. 갈 길이 멀면
  걸음 사이를 0.12초로 줄여 15초가 됐다. 도착해서 어슬렁거리는 모습은 그대로다

화면에서 확인했다: 15초에 도착(거리 1) → 목재 0 → 30초에 2 → 45초에 3.
