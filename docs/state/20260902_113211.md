### 결정 사항 (ADR 0008)

- **localStorage에 JSON 한 덩이, 슬롯 하나.** 32×32 맵에서 약 25KB라 IndexedDB의 비동기 API와
  스키마 관리를 감수할 이유가 없다.
- **버전이 다르면 읽지 않는다.** 블록·아이템 식별자가 리터럴이라 값이 바뀌면 예전 저장이
  예외 없이 잘못 읽힌다 — 흙이 돌이 되는 식으로 조용히.
- **지형만 base64.** 저장의 대부분이고 자동 저장이 반복되므로 크기가 곧 비용이다. 나머지는
  JSON 그대로 둬 디버깅 가능하게 남겼다.
- **파생 자료구조는 저장하지 않는다.** 건물 점유 맵은 목록에서 다시 만든다. 함께 저장하면
  원본과 어긋난 저장이 생길 수 있다.
- **진행 중인 동작은 저장하지 않는다.** 이동·휘두르기·배회는 버리고, 건축 남은 시간과 노드
  리스폰 시간은 저장한다 — 앞은 동작이고 뒤는 마을의 상태다.
- **손상은 부위별로 다르게.** 지형·창고 손상은 저장 전체를 거절하고, 인벤토리 슬롯 하나나
  없어진 블루프린트를 가리키는 건물은 그것만 버린다.

### 브라우저에서 잡은 버그 — "새로 시작"이 동작하지 않았다

저장을 지우고 `location.reload()`를 부르면, 페이지가 닫히며 `pagehide` 저장이 현재 상태를
한 번 더 써서 **방금 지운 저장을 즉시 되살렸다.** "되돌리기"도 같은 이유로 아무 일도 하지
않았다. 단위 테스트로는 잡히지 않는 종류였고, 실제로 눌러 보다 발견했다.

고치면서 "언제 저장할지"를 `SaveSession`이라는 값 객체로 뽑고 `suspend()`를 뒀다. 이제 그
상황이 테스트로 고정돼 있다("멈춘 뒤 지운 저장이 되살아나지 않는다").

## 검증 결과

- `npm run typecheck` / `npm run build` — 통과 (JS 70.2kB)
- `npm test` — **591개 통과** (36개 파일)
  - `save`(21개): 바이트 왕복(길이가 3의 배수가 아닌 경우 포함), 잘린 저장 거절, 버전 검사,
    지형 왕복, 열 높이 상한 초과 거절, 인벤토리 손상 슬롯만 버리기
  - `SaveStore`(10개): 없는 저장·손상된 JSON·용량 초과·접근 차단, **손상된 저장을 지우지 않음**
  - `SaveSession`(15개): 자동 저장 간격, 저장할 때만 스냅샷 생성, **멈춘 뒤 지운 저장이
    되살아나지 않음**(실제 버그 회귀)
  - `GameSave`(20개): 지형 변경분·인벤토리·도구·건물 점유·건축 잔여 시간·주민·요청·레벨 보존,
    두 번 왕복해도 동일, 손상 저장 거절
  - `playthrough`(+2개): **봇 플레이 중간에 저장/불러오기를 끼워도 레벨 5 도달**
- **브라우저 실제 확인**
  ```
  파기 후:        보유 흙 3 · 플레이어 (20, 15)
  수동 저장:      "11:30 저장됨" · 토스트 "저장했습니다" · localStorage 25,723바이트
  새로고침:       토스트 "이어서 시작합니다" · 위치 (20,15) · 보유 흙 3 · 마을 그대로
  새로 시작 1회:  버튼이 "한 번 더"로 바뀜(확인 창 없이)
  새로 시작 2회:  위치 (15,15) · 보유 없음 · localStorage 비워짐
  ```
