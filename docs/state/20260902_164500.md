# 작업 상태 — 로드맵 03 Phase 6 몬스터 침입과 방어

- **일자**: 2026-09-02
- **브랜치**: dev
- **직전 상황**: Phase 5에서 직업과 자동 생산을 넣었다. 테스트 840개.

## 이번에 한 일

기획서 9절의 "몬스터 침입 이벤트(방어 미니게임 형태로)"를 넣었다. 로드맵이 이 Phase의
위험을 "전투를 얼마나 깊게 만들 것인가"로 짚고 착수 시점에 정하라고 했다.
**정한 깊이는 얕다** — 결정과 근거는 ADR 0017에 있다.

### 세 줄로 요약되는 깊이

1. **플레이어는 다치지 않는다.** 체력도 죽음도 부활도 없다. `Raid`에 플레이어 체력이라는
   값이 아예 없다. 위험은 플레이어가 아니라 마을에 온다.
2. **건물은 부서지지 않고 손상된다.** 손상된 건물은 사라지지 않고 기능만 멈춘다 —
   새 주민이 안 들어오고, 생산이 멈추고, 마을 점수에서 빠진다. 수리비는 원래 자재의 1/4.
3. **밤 하나가 한 판이다.** 해가 뜨면 남은 몬스터는 물러간다. 싸움이 낮의 채집을
   잡아먹으면 루프가 끊긴다.

### 준비할 수 있는 침입

레벨 4부터, **이틀에 한 번**, 마릿수는 1 + (레벨-4)/2(최대 5), 체력 3대.
침입 여부는 **날짜만 보고** 정한다 — 무작위면 "오늘 올까"를 알 수 없고, 준비할 수 없는
방어는 미니게임이 아니라 사고다.

### 방어는 건축이다

- **울타리**(목재 3): 몬스터는 건물이 있는 칸을 지나지 못한다. 새 규칙을 만들지 않았다 —
  이동 판정에 "건물이 없을 것"을 더한 것이 전부다.
- **망루**(목재 8 + 돌 10 + 철광석 2): 가까이 온 몬스터를 스스로 쫓는다. 자리를 비운
  밤에도 마을이 버틴다.

이 게임에서 답은 언제나 "무엇을 지을까"여야 한다.

### 보상과 조작

물리치면 **마을 경험치**를 준다. 자원을 주면 사냥이 채집보다 나은 순간이 생기고, 그러면
방어 게임이 된다. 조작은 새 키 없이 `Space`가 **몬스터 → 손상 건물 → 자원 → 지형** 순으로
본다(ADR 0012의 "키를 늘리기 전에 문맥 재사용을 먼저 본다").

## 검증 결과

- `npm run typecheck` / `npm run build` — 통과 (JS 121.3kB)
- `npm test` — **860개 통과** (47개 파일, 840 → 860)
  - `raid`(신규 20개): 레벨·주기·마릿수 규칙, 몰려옴과 물러감, **부수지 않고 손상**,
    손상된 건물은 기능이 멈춤, **플레이어에게 체력이 없음**, 도구로 쫓기, 경험치 보상,
    수리와 자재 부족, 울타리가 길을 막음, 저장 왕복, **선택적 필드라 예전 저장도 읽힘**
  - `blueprints`: 울타리·망루가 목록에 들어온 것을 반영(총 9종 — 숫자 키 상한과 같다)
- **통과 플레이**: 봇이 방어를 전혀 하지 않아도 레벨 10에 도달한다(4.9분 → **5.1분**).
  침입이 진행을 막지 않으면서 대가는 있는 세기라는 뜻이다.
- 저장 형식 버전은 그대로 2다. 침입과 손상 모두 **선택적 필드**로 담았다.
- **브라우저 실제 확인은 하지 못했다** — 이 환경에 브라우저가 없다.

## 남겨 둔 것

- 몬스터가 경로 탐색을 하지 않으므로 **울타리를 완전히 두르면 갇힌다.** 지금은 벽 앞에서
  멈춰 있다가 해가 뜨면 물러간다. 완전 봉쇄가 최적 전략이 되는 것을 막으려면 문을 부수는
  규칙이 필요한데, 그것은 다음 판단이다.
- 봇이 방어도 수리도 하지 않는다. 침입 강도는 판단값이며 Phase 8에서 측정한다.
