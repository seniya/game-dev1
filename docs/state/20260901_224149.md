## 이번에 한 일

### 기술 스택 확정

TypeScript + Canvas 2D + Vite + Vitest로 결정하고 `docs/adr/0001-기술-스택-선정.md`에 기록했다.
Phaser 3와 Three.js를 검토했으나, 기획서 3절이 카메라 회전을 배제하고 5.1절이 커스텀 깊이 정렬을
요구하므로 엔진의 이득이 작고 통제권 상실이 크다고 판단했다. 로드맵의 미해결 항목 중 "기술 스택"이 해소됐다.

### 설계상 지킨 규칙

- **브라우저 API와 순수 로직 분리**: 스텝 수 계산은 `planSteps` 순수 함수, `requestAnimationFrame`
  연결만 `GameLoop`이 담당. 테스트가 jsdom 없이 node 환경에서 돌아간다.
- **spiral of death 방지**: 프레임당 스텝 상한 5. 초과 시간은 버려 다음 프레임에 빚을 넘기지 않는다.
- **DPR 처리**: 캔버스 버퍼는 `devicePixelRatio`를 곱해 잡고 컨텍스트를 스케일. 이후 모든 그리기
  코드는 CSS 픽셀 좌표만 쓴다.

## 검증 결과

- `npm run typecheck` — 통과 (strict, noUnusedLocals, exactOptionalPropertyTypes)
- `npm test` — 23개 테스트 통과 (4개 파일, 약 0.14초)
  - `planSteps`: 정확한 배수 / 잔여 이월 / 상한 클램프 / 빚 누적 없음 / 음수·NaN 방어 / 예외
  - `FpsCounter`: 일정 간격 환산 / 윈도우 밀어내기 / 비정상값 무시 / reset
  - `GameLoop`: rAF 스텁으로 프레임 주입 — render는 프레임당 1회, update는 흐른 시간에 비례,
    긴 정지 후 상한 클램프, alpha 범위, stop 후 미예약, 중복 start 무시
  - `GameState`: 초기값 / 60스텝 누적
- `npm run build` — 성공 (JS 3.78kB, CSS 0.45kB)
- `npm run dev` — Vite 개발 서버가 `index.html`, `src/main.ts`, `src/styles.css`를 200으로 서빙

**미검증**: 실제 브라우저에서 캔버스가 그려지고 FPS 숫자가 갱신되는지는 아직 육안 확인하지 않았다.
로드맵 Phase 0의 완료 기준("검은 캔버스와 FPS 표시")을 닫으려면 `npm run dev`로 열어 확인이 필요하다.

### Phase 1 — 아이소메트릭 렌더링 기반

로드맵 Phase 1의 작업 항목:

- `src/core/coordinates.ts` — 그리드 좌표(x, y, z) ↔ 화면 좌표 양방향 변환
- 마름모 타일 렌더링 및 깊이 정렬 규칙 확립
- 카메라: 팬(드래그), 줌 인/아웃. **회전은 지원하지 않는다**
- 마우스 피킹: 커서 아래 타일 좌표 산출 → 하이라이트
- 화면 밖 타일 컬링

**Phase 1 시작 전에 정해야 할 것** (로드맵이 ADR 후보로 지목한 항목, ADR 0002가 된다):

- 타일 픽셀 치수 (예: 64×32 마름모)
- 좌표계 원점 위치와 축 방향
- z축(높이) 방향과 1레이어의 픽셀 높이
- 깊이 정렬 키 산출 공식

이 규약은 Phase 2 이후 전부가 의존하므로 코드보다 먼저 문서로 못 박는다.
