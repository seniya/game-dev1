## 이번에 한 일

### 소리를 합성한다 (ADR 0010)

음원 파일도 가져올 수 없으므로 아트와 같은 해법을 썼다 — **Web Audio의 오실레이터와
노이즈로 합성한다.**

- **재질은 필터 주파수로 나눈다.** 흙 700Hz, 나무 1400Hz, 돌 2600Hz. 같은 백색 소음에서
  서로 다른 재질감이 난다. 파일 없이 소리를 구분되게 만드는 핵심이다.
- **알림음은 5음 음계의 짧은 톤을 이어 붙인다.** 완공은 3음 상행, 레벨업은 4음 상행처럼
  "얼마나 큰일인가"가 길이로 전달된다.
- **배경음은 루프가 아니라 생성이다.** 음계에서 음을 골라 2.6초씩 늘여 잇는다. 같은 구간이
  반복되지 않고 파일도 필요 없다.

### 브라우저 자동재생 정책

`AudioContext`를 생성자가 아니라 첫 사용자 입력(`unlock()`)에서 만든다. 그전의 재생 요청은
조용히 무시한다 — 소리가 안 나는 것보다 예외로 게임이 죽는 것이 나쁘다. 탭을 옮겼다 오면
정지 상태로 남을 수 있어 `unlock()`이 `resume()`도 겸한다.

잠금 직후 배경음 첫 음은 1.2초 미룬다. 잠금을 푼 것은 사용자가 무언가를 눌렀다는 뜻이고,
그 조작음과 겹치면 둘 다 뭉개진다.

### 규칙은 소리를 모른다

`Game`은 사건에 `cue`만 붙여 알리고(`migration`·`levelUp`·`buildDone`·`requestNew`·
`requestDone`), 그것을 문구로 쓸지 소리로 쓸지는 UI가 정한다. Phase 7에서 만든 알림 통로를
그대로 재사용했다.

### 연출은 그리드 좌표에 매인다

파편과 글자를 화면 좌표로 들고 있으면 카메라를 움직이는 동안 연출만 화면에 붙어 따라다녀
어색해진다. 그리드 좌표로 두고 매 프레임 변환한다(테스트로 고정).

## 검증 결과

- `npm run typecheck` / `npm run build` — 통과 (JS 93.9kB)
- `npm test` — **633개 통과** (39개 파일)
  - `AudioPlayer`(15개): 잠금 전 재생 무시, 컨텍스트 한 번만 생성, 정지 상태 재개,
    **오디오가 없는 환경에서도 죽지 않음**, 볼륨 순환, 음소거 시 소리 생성 안 함,

  - `Effects`(13개): 파편 수명과 이동·감쇠, **카메라를 움직이면 함께 움직임**,
    글자는 끝에서만 옅어짐, 높이 반영, 그린 뒤 전역 상태 복원
- **브라우저 실제 확인** — 오디오 노드 생성을 가로채 셌다
  ```
  시작:          컨텍스트 0
  첫 파기:       컨텍스트 1, 노이즈 소스 1   ← 클릭이 오디오를 켰다
  연속 파기:     오실레이터 4, 노이즈 2
  3.5초 대기:    오실레이터 6                ← 배경음 한 음(디튠 2개)
  볼륨 버튼:     소리 ●●○ → ●●● → 끔 → ●○○
  설정 저장:     {"volumeStep":1}
  ```
  캡처로 "+1 흙" 떠오르는 글자와 흙색 파편이 튀는 것을 확인했다.
