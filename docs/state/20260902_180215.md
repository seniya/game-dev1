## 이번에 한 일

**로드맵 03이 넣은 것을 처음으로 화면에서 봤다.** 테스트 889개가 규칙을 지키고 있었지만,
화면에서만 드러나는 결함이 여섯 개 있었다.

### 확인용 개발 훅

`import.meta.env.DEV`일 때만 `window.__town`에 게임 상태를 노출했다. 밤·침입·손상·동굴처럼
한참 키워야 나오는 화면을 확인하려면 상태를 직접 옮길 수 있어야 한다. 프로덕션 빌드에서는
조건이 false로 치환돼 블록이 사라진다.

## 화면에서만 드러난 결함 여섯 개

| # | 무엇 | 왜 테스트가 못 잡았나 |
|---|---|---|
| 1 | **동굴에서 플레이어가 통째로 가려진다** | 벽 높이가 최대치(5)라 앞 열이 캐릭터를 덮었다. 엔티티는 정상적으로 만들어지므로 테스트는 통과한다 |
| 2 | **수정 광맥이 돌 광맥과 똑같이 그려진다** | 엔티티가 `iron: boolean` 하나뿐이라 수정이 `false`로 떨어졌다. 동굴에서 가장 귀한 것이 가장 흔한 것과 구분되지 않았다 |
| 3 | **동굴에서 "초원"이라고 표시한다** | `zoneAt`이 동굴 지형에도 돌았다. 구역은 마을 중심에서의 거리인데(ADR 0005) 동굴에는 마을이 없다 |
| 4 | **손상된 건물 때문에 "건물 0"** | 규칙은 맞다(손상은 기능이 멈춘다). 그러나 눈앞에 건물이 있는데 0으로 보인다 |
| 5 | **밤이 낮처럼 보인다** | 빛 반경 8칸이 확대 상태에서 화면 대부분을 덮었다. 22시가 흐린 오후 같았다 |
| 6 | **동굴에서 "Space: 수리" 안내** | 지상의 손상 건물 수를 그대로 셌다. 동굴에서는 할 수 없는 일이다 |

여기에 `favicon.ico` 404 하나를 더 고쳤다(인라인 SVG로, ADR 0009의 "에셋은 코드로" 규약과 같은 결).

### 고친 방법

1. **동굴 벽 높이 5 → 3.** 바닥(1)과의 차가 2라 등반 한계 1칸(ADR 0004)을 여전히 넘지 못해
   벽 노릇은 그대로 하면서, 앞 열이 뒤 칸의 캐릭터를 덮지 않는다.
2. **광맥 엔티티가 `ore: 'stone' | 'iron' | 'crystal'`을 갖는다.** 수정은 보라(#9a86e0),
   철광석은 주황, 돌은 옅은 회색 — 인벤토리 바의 아이템 색과 맞췄다.
3. 디버그 표시가 구역 대신 **있는 곳의 이름**을 받는다. 지상은 구역, 동굴은 맵 이름.
4. HUD가 `건물 47 (손상 1)`로 빠진 만큼을 알린다.
5. 밤의 빛 반경 8 → 5, 어두워지는 반경 18 → 14.
6. 수리 안내를 마을에서만 센다.

테스트 875 → **889개**. 고친 것마다 테스트를 붙였다 —
"벽이 캐릭터를 가릴 만큼 높지 않다", "광맥 세 종류가 서로 다른 스프라이트를 쓴다" 등.

## 성능 측정 (로드맵 04 Phase 2)

지형을 평탄화하고 집을 채워 후반 규모를 만든 뒤, 밤·침입·색조·어둠을 모두 얹고 쟀다.

| 항목 | 값 |
|---|---|
| 건물 | 47채(작은 집·큰 집 섞음) |
| 주민 | 53명 |
| 몬스터 | 5마리(침입 중) |
| 화면 오브젝트 | 347개 |
| **프레임** | **60fps** (줌 0.55, 맵 전체가 화면에 들어옴) |
| **시뮬레이션 스텝** | **0.016ms** (예산 16.7ms의 0.1%) |

**여유롭다.** 로드맵 04 Phase 2는 최적화가 아니라 이 측정을 테스트로 고정하는 일로 줄어든다.

## 눈으로 보고 남긴 것 (아직 안 고침)

  자리를 다툰다 → 로드맵 04 Phase 3.
- **확대하면 어둠이 옅어진다.** 반경이 타일 기준이라 그렇다. 줌 1.0에서는 충분히 어둡다.
  의도된 성질로 두되 기록해 둔다.
- **플레이어가 작다.** 커서 마름모보다 작아 보인다. 어두운 곳에서 특히.
- **HUD가 반투명이라 아래 엔티티가 비친다.** 몬스터가 HUD 뒤로 지나가면 글자와 겹친다.
