## 이번에 한 일

### 자원 모델 확정 (ADR 0005)

- **구역은 마을 중심에서의 체비쇼프 거리로 나눈다** — 초원(0~7) → 숲(8~12) → 산악(13~).
  Phase 8의 단계 개방이 반지름 하나로 끝나고, 사각 띠라 아이소메트릭 화면에서 마름모 띠로
  보여 타일 격자와 결이 맞는다.
- **자원은 지형이 아니라 별도 노드** — 희소하고 "이 칸에 노드가 있나?"가 유일한 질문이라
  Map 조회가 맞다. 노드를 부순 뒤 같은 칸의 지형을 파는 일도 자연스럽게 성립한다.
- **아이템 타입을 블록과 분리** — 목재는 지형에 없고, 빈칸은 아이템이 아니며, 철광석은
  아이템이지만 지형에 되놓을 수 없다. 이 비대칭을 한 타입으로 표현하면 쓰이지 않는 값이 생긴다.

| `src/sim/ResourceField.ts` | 노드 배치(결정적)·채집·리스폰·조회. `addNode`로 사후 추가 가능 |

`Game.actAt`이 주 행동의 단일 입구가 됐다. 노드가 살아 있는 칸에는 블록을 쌓을 수 없고
(나무가 흙에 묻히면 안 된다), 플레이어 시작 위치도 노드가 없는 칸을 고른다.

## 검증 결과

- `npm run typecheck` / `npm run build` — 통과 (JS 30.5kB)
- `npm test` — **315개 통과** (21개 파일)
  - `ResourceField`(25개): 같은 시드 같은 배치, 뚫린 칸 제외, **철광석은 산악에만**,
    초원에는 나무만, 숲이 초원보다 나무가 빽빽함, 상위 등급이 더 적은 타격으로 부숨,
    부서진 노드는 길을 막지 않음, 리스폰 후 내구도 회복
  - `Game`(+12개): 나무는 도끼로만, 노드가 있는 칸은 지형이 아니라 노드가 대상,
    부순 뒤에는 같은 칸의 지형을 팔 수 있음, 살아 있는 노드 위에는 쌓기 거부
  - `items`/`zones`/`ItemStash`(19개): 왕복 변환, 구역 경계, 부분 인출 거부
- **브라우저 실제 확인** — 초원에서 걸어 나가 숲의 나무를 벌목했다.
  ```
  발견:    타일 (23, 16) 나무 100% · 숲
  벌목 1:  나무 67%   · 보유 없음
  벌목 2:  나무 33%   · 보유 없음
  벌목 3:  흙         · 보유 목재 3   ← 부서지며 드롭
  벌목 4~5: 변화 없음                  ← 도끼로는 흙을 팔 수 없다
  ```
  축소 캡처에서 구역별 분포를 확인했다 — 중앙 초원은 비어 있고, 중간 띠에 나무가 빽빽하고,
  바깥 띠에 광맥이 몰려 있다. 60fps 유지.

Phase 4의 완료 기준(나무를 베어 목재를, 광맥을 캐서 돌/철광석을 얻는다)을 충족한다.
