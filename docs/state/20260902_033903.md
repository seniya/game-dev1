# 작업 상태 — Phase 8 마을 레벨과 해금 완료

- **일자**: 2026-09-02
- **브랜치**: dev
- **직전 상황**: Phase 7 완료. 주민과 요청은 있으나 진행 축(마을 레벨)이 없었다.

## 이번에 한 일

기획서 6절의 진행 구조를 구현했다. 스토리가 없으므로 마을 레벨이 유일한 진행 축이다.

### 결정 사항 (ADR 0007)

- **점수 = 건물 × 2 + 주민 × 3 + 요청 보상 합계.** 주민이 가장 무겁다(집을 지어야만 늘어나므로
  건물 점수를 이미 한 번 포함한 성과다). 요청은 개수가 아니라 보상 합계를 써서 시설 요청(5점)과
  납품 요청(2점)의 서열을 유지한다.
- **레벨은 저장하지 않고 점수에서 파생한다.** 점수와 레벨이 어긋난 상태가 존재할 수 없다.
- **구역 개방은 채집만 막는다.** 이동을 막으려면 벽이 필요한데 그 벽은 파고 쌓을 수 있는
  지형과 충돌한다. 구역 잠금은 규칙이지 지형이 아니다. 부수 효과로 "미리 둘러볼 수는 있지만
  아직 캘 수는 없다"는 동기가 생긴다.
- **초원과 숲은 처음부터 열려 있다.** 숲을 잠그면 첫 집의 목재 12를 초원의 드문 나무(5%)로만
  모아야 해서 시작이 지루해진다.
- **중급 곡괭이와 큰 집이 같은 레벨 3에 열린다.** 철광석은 중급 곡괭이를 요구하고 큰 집은
  철광석을 요구하므로, 다른 레벨에 열리면 진행이 막히거나 쓸모없는 해금이 된다.

## 검증 결과

- `npm run typecheck` / `npm run build` — 통과
- `npm test` — **496개 통과** (29개 파일)
  - `village`(26개): 가중치 서열, 임계값 단조 증가와 간격 확대, 레벨 상한, 구간 진행도,

    도구 등급 상승, 새 블루프린트 등장, 레벨 하락 없음, 잠긴 구역 채집 거절,
    **잠긴 구역이라도 지형은 팔 수 있음**, 안내 문구의 "(잠김)" 표시
- **브라우저 실제 확인** — 채집 → 건축 3채 → 레벨업 → 구역 개방
  ```
  시작:            마을 레벨 1 · 주민 0 · 건물 1 · 2/8 | 1차 목표: 마을 레벨 5
  산악 노드(레벨1): 철광석 광맥 100% (잠김)
  목재 21 · 돌 6 확보 → 작업대 3채 건축
  결과:            마을 레벨 2 · 주민 0 · 건물 4 · 8/20
  토스트:          해금: 산악 개방 / 중급 도끼 / 중급 삽 / 창고 설계도
  산악 노드(레벨2): 나무 100%   ← "(잠김)" 사라짐
  ```

특히 지형을 파 내려갈 때 **같은 열을 계속 겨누려면 조준점을 레이어당 16px 내려야 한다**는
점을 반영했다 — 파낼수록 그 열의 윗면이 화면에서 내려가기 때문이다. 이 보정이 없으면 뒤쪽
열을 찍게 되어 채굴이 되지 않는다.
