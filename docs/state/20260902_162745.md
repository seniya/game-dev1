# 작업 상태 — 로드맵 03 Phase 4 낮과 밤

- **일자**: 2026-09-02
- **브랜치**: dev
- **직전 상황**: Phase 3에서 동굴에 수정·해금·대장간·어둠을 넣었다. 테스트 796개.

## 이번에 한 일

시간축을 넣었다. 이 Phase의 목적은 분위기가 아니라 **뒤따르는 두 Phase의 전제**다 —
기획서 5.4의 NPC는 "정해진 시간대에 배회"하고, 9절의 몬스터 침입은 밤에 오는 것이 자연스럽다.
결정은 ADR 0015에 있다.

### 저장 형식을 바꾸지 않았다

로드맵은 이 Phase를 "형식이 바뀌는 세 번 중 두 번째"로 셌지만, **누적 시뮬레이션 시간이
이미 저장되고 있었다.** 시각은 그 값에서 계산하면 된다.

ADR 0011이 배수형 보너스를 두고 내린 판단과 같은 규칙이다 — 다른 값에서 유일하게 결정되는
것은 저장하지 않는다. 마이그레이션 부담도 그만큼 줄었다.

### 하루는 4분, 아침에 시작한다

- 통과 플레이(4.9분)에 **2일**이 흐른다. 봇 5분이 사람 40~60분이므로 사람 기준 하루가 약
  4분이고, 첫 세션에 열 번 남짓 해가 뜨고 진다.
- 07:40 무렵에 시작한다. 어두운 화면으로 시작하면 처음 켠 사람이 할 일을 찾기 어렵고,
  정오에 시작하면 첫 밤이 너무 빨리 온다.
- 낮 42% · 밤 38% · 전환 20%. 밤이 길면 기다리는 시간이 된다.
- 이 숫자는 통과 플레이 테스트가 지킨다(한 판에 2~10일).

### 어둠이 두 종류가 됐다

| | 동굴(ADR 0014) | 밤 |
|---|---|---|
| 성격 | 장소 | 시간 |
| 밝은 반경 | 5칸 | 8칸 |
| 최대 세기 | 0.8 | 0.45 × 밤의 정도 |
| 색조 | 없음 | 푸른 밤 + 전환의 노을 |

동굴 안에서는 시간대 색조를 얹지 않는다 — 하늘이 보이지 않는 곳이다. 밤의 시야를 동굴보다
넓고 옅게 둔 이유는 마을을 돌아다니는 것이 막히면 안 되기 때문이다. **밤은 불편함이지
벌칙이 아니다.**

전환은 이어 붙인다. 해가 툭 꺼지면 사이클이 사건처럼 보이는데, 여기서 낮밤은 배경이다.

### 규칙과 표현을 나눈 자리

`Game.atmosphere()`가 색조와 빛(중심·반경·세기)을 값으로 돌려주고, 렌더러는 "밤"도 "동굴"도
모른 채 그것을 그린다. 두 어둠이 한 경로로 그려지고, 규칙만 보고 "밤에 동굴에 있으면
어떻게 되는가"를 답할 수 있다(동굴의 어둠만 적용된다).

### 그 밖에

- 상단에 `3일차 07:40 · 낮` 한 조각을 더했다(대사창 없이, 기획서 7절).
- 첫 밤에 "밤에는 시야가 좁아집니다"를 한 번만 알린다 — 화면이 눈에 띄게 달라지는 순간에
  이유를 주는 것이 기존 힌트 체계(로드맵 02 Phase 5)의 쓰임과 같다.

## 검증 결과

- `npm run typecheck` / `npm run build` — 통과 (JS 108.2kB)
- `npm test` — **821개 통과** (45개 파일, 796 → 821)
  - `daycycle`(신규 20개): 하루의 흐름과 랩어라운드, 구간 비율, 어둠의 양, 색조,
    시계 표시, **저장 없이 되살아나는 시각**, 첫 밤 힌트
  - `WorldRenderer`(+3): 색조 덮기, 대낮에는 얹지 않음, 색조 → 빛 순서
  - `playthrough`(+1): 한 판에 2~10일이 흐른다(측정 결과 2일)
- **브라우저 실제 확인은 하지 못했다** — 이 환경에 브라우저가 없다.

## 남겨 둔 것

**밤이 아직 아무것도 바꾸지 않는다.** 보이는 범위만 좁아질 뿐 할 일은 낮과 같다.
그것을 채우는 것이 Phase 5(직업의 시간대)와 Phase 6(야간 침입)이다.
