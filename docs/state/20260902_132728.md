## 1. 고를 수 없던 설계도를 고쳤다

로드맵 03 Phase 1을 쓰다가 발견한 실제 결함이다.

숫자 키가 `Digit1~3`뿐인데 레벨 2에서 창고, 레벨 3에서 큰 집이 열린다. `BuildPanel`에는
클릭 핸들러가 없어서 **네 번째와 다섯 번째 설계도는 어떤 입력으로도 고를 수 없었다.**
패널은 `4.` `5.`까지 번호를 붙여 놓아 안내와도 어긋나 있었다.

봇 통과 플레이가 `Game.selectBlueprint`를 직접 불러 마을 레벨 10까지 가기 때문에
**테스트 700개가 이것을 잡지 못했다.** 입력 계층을 아무도 지나가지 않았던 것이다.

- 숫자 키를 1~9로 넓히고(`SLOT_KEY_COUNT`), 범위 밖 번호는 받는 쪽이 무시하게 뒀다.
- 조작 안내가 실제 설계도 수를 말한다(`1~5: 설계도`).
- `SLOT_KEY_COUNT >= BLUEPRINTS.length`를 테스트로 지킨다 — 로드맵 03이 설계도를 더 늘린다.

## 3. Phase 1 — 키보드만으로 플레이

### 방향키가 겨냥한다 (ADR 0012)

행동 대상이 `pointer.hovered` 하나였다. 마우스가 없으면 **대상 자체를 고를 수 없어**
Space가 아무 일도 하지 않았다. 대상을 입력 장치에서 떼어냈다.

- `src/core/cursor.ts` — 플레이어 기준 오프셋으로 겨냥한 칸을 정한다. 걸으면 따라오고,
  걷는 방향으로 되잡되 **건축 모드에서는 찍어 둔 부지를 지킨다.**
- 방향키는 걷기가 아니라 겨냥이다. ADR 0004에서 방향키는 WASD의 중복 매핑이었으므로
  기능을 잃지 않고 옮길 수 있는 유일한 키였다. ADR 0004에 개정 표시를 남겼다.
- 마지막에 쓴 입력이 이긴다. 같은 칸이 계속 들어오는 것은 "마우스가 움직였다"로 보지 않는다 —
  마우스를 책상에 둔 채 키보드로 플레이할 수 있어야 한다.
- 커서 범위는 축별 6칸. 건축은 사거리 제한이 없어 커서가 필요하고, 무한이면 화면 밖으로 나간다.
  **사거리 규칙은 UI가 아니라 `Game`이 갖는다** — 두 곳에 두면 어긋난다.

### 나머지 조작

- `Q`로 쌓기(마우스 우클릭에 해당), `+`/`-` 확대, `C` 추적 복귀.
- 팬 키는 만들지 않았다. 방향키가 겨냥이라 팬까지 얹으면 한 키를 두고 다툰다.
  커서 범위가 6칸이고 카메라가 플레이어를 따라가므로 겨냥할 곳은 언제나 화면 안이다.
- **포커스가 버튼에 있으면 키를 브라우저에 넘긴다.** 그러지 않으면 Space가 게임 행동으로
  먹혀 저장 메뉴 버튼이 눌리지 않는다. 포커스 표시(`:focus-visible`)도 넣었다.
- 조작 안내를 새 규약에 맞췄다.

### `InputRouter`로 입력 계층을 테스트 가능하게 만들었다

키 연결이 `main.ts`에 흩어져 있어 DOM 없이는 조작을 검증할 수 없었다. `src/ui/InputRouter.ts`는
캔버스도 DOM도 보지 않는다 — 가짜 이벤트 대상만 있으면 키 입력만으로 채집·쌓기·예치·건축·
철거·요청을 전부 돌려볼 수 있다.

**옮기는 과정에서 새 테스트가 버그를 하나 잡았다.** `hooks.report?.(game.actAt(target))`처럼
쓰면 옵셔널 호출이 **인자 계산까지 건너뛰어**, 표현 창구가 없을 때 행동 자체가 사라진다.
결과를 먼저 계산하고 넘기도록 고쳤다.
