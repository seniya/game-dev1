# 작업 상태 — 로드맵 03 Phase 2 다중 맵 기반

- **일자**: 2026-09-02
- **브랜치**: dev
- **직전 상황**: Phase 0(배포 준비)·Phase 1(키보드 전용 조작) 완료. 테스트 731개.

## 이번에 한 일

ADR 0003이 "동굴은 별도 맵으로 다룬다"고 전제해 둔 것을 실제로 쓸 수 있게 구조를 열었다.
**콘텐츠가 아니라 구조**다 — 로드맵 03이 "먼저 구조를 열고, 그 다음에 콘텐츠를 넣는다"로
순서를 잡았고, 동굴의 자원과 어둠은 Phase 3의 몫이다.

### `Game`이 맵을 여럿 든다 (ADR 0013)

`terrain`·`resources`가 `readonly` 필드에서 **지금 있는 맵을 가리키는 게터**가 됐다.
호출부(렌더러·피킹·규칙)는 그대로다 — 맵을 늘리는 일이 기존 코드를 휘젓지 않는 형태를 골랐다.

- 동굴은 **처음 들어갈 때** 시드에서 만들어진다. 가 보지 않은 맵을 들고 있을 이유가 없고,
  단위 테스트가 작은 지형 하나로 게임을 세울 수 있어야 한다.
- 맵 시드는 세계 시드에 맵 종류를 섞어 만든다. 섞지 않으면 동굴이 지상과 같은 모양이 된다.
- 떠난 맵도 함께 흐른다. 마을의 건축·주민·리스폰이 동굴에 있는 동안 멈추면 "오래 있을수록
  손해"라는 규칙이 생긴다.

### 마을은 지상에만 있다

맵 속성 하나(`isVillageMap`)로 규칙을 가른다. 동굴에서는 건축·철거·미리보기가 거부되고
(`notVillage`), 창고에 손이 닿지 않고, 지상 건물이 칸을 막지 않고, 구역 잠금이 없고,
주민과 건물을 그리지 않는다.

### 동굴 지형은 자료구조를 바꾸지 않고 만들었다

높이맵은 천장을 표현할 수 없으므로(ADR 0003) 동굴을 **위에서 내려다본 통로**로 그린다.
벽은 최대 높이까지 채운 암반 기둥, 파낸 자리는 높이 1. 등반 한계가 1칸이라(ADR 0004)
벽은 따로 규칙 없이 통행을 막는다.

생성은 방을 파고 **직전 방과 L자 통로로 잇는** 방식이다. 노이즈로 뚫으면 닿을 수 없는 방이
생기는데, 이어 붙이며 파면 연결이 생성 방식에서 보장된다. 테스트가 너비 우선 탐색으로 고정한다.

### 통로는 지형에서 파생되고 저장하지 않는다

- 지상 입구: 마을 중심에서 가장 먼 칸 → 구역이 거리로 나뉘므로(ADR 0005) 자동으로 산악이다.
  같은 거리면 걸어 들어갈 길이 많은 칸을 고른다(구석은 이웃이 둘뿐이라 답답하다).
- 동굴 출구: 파낸 칸 중 중앙에 가장 가까운 것.

실제 생성 지형(32×32, 세 시드)에서 통로가 산악 구역에 놓이고 시작 지점에서 **걸어갈 수
있음**을 테스트로 고정했다.

### 저장 형식 v2와 마이그레이션 (ADR 0008 개정)

버전이 처음으로 올랐다. 그러면서 "버전이 다르면 읽지 않는다"의 대가가 드러났다 —
**거절은 곧 사용자의 마을을 지우는 일이다.** 로드맵 03은 형식을 세 번 바꿀 예정이라
그대로 두면 마을이 세 번 사라진다.

규칙을 좁혔다: **없어진 값을 시드에서 재현하거나 안전한 기본값으로 채울 수 있으면 옮긴다.**
v1은 맵이 하나뿐이었으므로 그 지형이 지상이고 동굴은 아직 안 가 본 것으로 두면 된다.

### 조작

`F`로 통로를 탄다. 통로 위가 아니면 이유를 알린다. 키보드만으로 동굴에 들어갔다 나오는
경로를 `InputRouter` 테스트가 지킨다(Phase 1이 만든 입력 계층 테스트가 여기서 값을 했다).
