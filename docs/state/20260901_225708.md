## 이번에 한 일

### 좌표계 규약 확정 (ADR 0002)

Phase 2 이후 모든 코드가 의존하는 규약이라 코드보다 먼저 문서로 고정했다.
`docs/adr/0002-좌표계-규약.md`에 결정과 대안 검토를 기록했다. 요약:

- **좌표계 세 층**: 그리드 좌표(타일 단위, `src/core`) → 월드 좌표(px, 투영 적용) → 화면 좌표(카메라 적용).
  투영과 카메라를 분리해 `src/core`가 카메라를 모르게 유지한다.
- **타일 64×32 (2:1 마름모)**, 레이어 높이 16px. 2:1을 고른 이유는 대각선 이동이 정수 픽셀
  `(±32, ±16)`로 떨어져 타일 이음새와 팬 중 지터가 생기지 않기 때문이다.
- **축 방향**: x는 오른쪽-아래, y는 왼쪽-아래, z는 위쪽. z를 위로 잡으면 파기는 배열을 비우는 일,
  쌓기는 채우는 일이 되어 `z = 0..4` 인덱싱이 그대로 지형이 된다.
- **원점**: 그리드 `(0,0,0)`의 **윗면 중심**이 월드 원점. 지면 위에 서는 것들의 위치 계산이 덧셈 없이 끝난다.
- **그리기 순서**: `(x + y)` 1순위, `z` 2순위 오름차순. `x + y + z`를 쓰지 않은 이유는 우리 투영이
  진짜 등거리 투영이 아니어서(레이어 높이가 타일 높이의 절반) 같은 합을 갖는 겹치는 블록의
  순서가 임의로 정해지기 때문이다.
- **피킹**: 마름모 히트 테스트 없이 역변환 후 `Math.round`. 타일 중심이 격자를 이루므로
  "가장 가까운 중심"이 "그 점을 품은 마름모"와 같다.

### 설계상 지킨 규칙

- **프레임당 할당 없음**: 타일을 배열로 모아 정렬하지 않고 `x + y` 대각선을 직접 순회해
  같은 순서를 얻는다. 마름모도 꼭짓점 객체 없이 중심과 반폭·반높이로 그린다.
- **컬링**: 뷰포트 네 꼭짓점의 그리드 좌표를 감싸는 사각형을 쓴다. z가 큰 블록은 화면에서
  위로 밀려 그려지므로 `z = 0`과 최상단 레이어 양쪽으로 범위를 구해 합집합을 취한다.
- **브라우저 API 분리 유지**: `Camera`는 뷰포트 크기를 외부에서 받아 DOM에 의존하지 않으므로
  단위 테스트가 가능하다. DOM 이벤트는 `src/ui/PointerControls.ts`에만 있다.

### 도중에 잡은 버그

`pointerdown`에서 호버 타일을 갱신하지 않아, 이동 없이 바로 누르는 입력(터치 탭)에서는
대상 타일이 정해지지 않아 클릭 콜백이 아예 호출되지 않았다. `handlePointerDown`에서
호버를 갱신하도록 고치고 회귀 테스트를 추가했다. Phase 3에서 타일 클릭(파기)이 붙기 전에
발견해서 다행인 종류의 버그다.

## 다음 할 일

### Phase 2 — 복셀 지형: 파기와 쌓기

로드맵 Phase 2의 작업 항목:

- 지형 자료구조: `width × height × 5레이어` 블록 그리드, 블록 타입(흙/돌/철광석/빈칸)
- 높이 있는 지형 렌더링 — **측면 벽면 포함**. 현재 `WorldRenderer`는 윗면 마름모만 그리므로
  측면 사각형 두 면(좌·우)을 추가하고, 가려지는 면은 그리지 않는 판정이 필요하다
- 파기: 블록 제거 → 자원 획득, 아래 레이어 노출
- 쌓기: 보유 블록을 인접 유효 위치에 배치
- 깊이 제한 5레이어 강제
- **평탄도 판정 함수**: 지정 사각 영역이 같은 높이의 빈 지면인지 검사 (Phase 6 건축의 전제 조건)

**Phase 2 시작 전에 정할 것** (로드맵이 ADR 후보로 지목, ADR 0003이 된다):

- 지형 자료구조: 3D 배열(`Uint8Array` 평탄화 포함) vs 높이맵 + 타입맵.
  기획서 5.1이 파기로 생긴 **빈 공간**을 허용하므로 높이맵만으로는 표현이 안 될 가능성이 있다.
  동굴/오버행을 지형으로 허용할지 여부가 이 결정을 좌우한다 — 기획서에는 명시가 없다.
- 렌더링 성능 전략: 현재는 매 프레임 전부 다시 그린다. 레이어가 5배로 늘고 측면까지 그리면
  드로우콜이 수 배가 되므로, 오프스크린 캔버스 캐시나 변경 영역만 재그리기를 검토한다.

### 참고: `TileGrid`와 `WorldRenderer`는 Phase 2에서 크게 바뀐다

`TileGrid`는 크기·경계만 갖는 임시 구조이고, `WorldRenderer`는 z=0 윗면만 그린다.
Phase 2에서 지형 자료구조가 들어오면 둘 다 확장 대상이다. 반면 `coordinates.ts`와 `Camera`는
규약이 확정됐으므로 그대로 쓴다.

### 참고: Phase 6에서 다시 봐야 할 정렬 규칙

현재 깊이 정렬은 **한 타일·1레이어 높이 블록**을 전제한다. 여러 타일을 점유하는 건물(기획서 5.3)과
나무(Phase 4)는 단일 `(x, y, z)` 키로 순서를 정할 수 없어 점유 영역 기반 정렬이 따로 필요하다.
ADR 0002에 이 한계를 명시해 뒀다.
