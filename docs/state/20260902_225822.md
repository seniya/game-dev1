- **조작**: 키보드만으로도, 마우스만으로도 끝까지 된다

## 3. 다음에 할 일 (우선순위 순)

### (1) 배포를 켜는 일 — 사람의 손이 필요하다

저장소 **Settings → Pages → Source를 `GitHub Actions`로** 바꾼다. 그 뒤 Actions 탭에서
`deploy`를 손으로 한 번 돌리면(워크플로에 `workflow_dispatch`가 있다) 배포된다.

- 확인할 것: `https://seniya.github.io/game-dev1/`가 열리는지, 자산이 `/game-dev1/`
  경로에서 뜨는지, 저장·이어하기가 되는지
- 코드 쪽에 남은 일은 없다. `main`은 최신이고 `build` 잡은 매번 성공한다
- **이것이 왜 급한가**: 이 개발 머신은 사용자가 원격 접속하는 서버라 `localhost` 주소로는
  사용자가 게임을 볼 수 없다. 배포 주소가 유일한 경로다

### (2) 처음 잡는 사람에게 건네기 (로드맵 05 Phase 5)

준비는 끝났다. 남은 것은 **누구에게 건넬 것인가**뿐이다.

- 설명 없이 링크만 건넨다. 설명하면 그 사람은 더 이상 처음 잡는 사람이 아니다
- 30분 뒤 저장 메뉴의 **"기록 복사"**를 눌러 받은 글을 달라고 한다
- 그 글의 "없음"으로 남은 이정표와 "막힌 곳" 목록이 **다음 로드맵의 절반**이다
- 한 사람에게 두 번 시험할 수 없다

### (3) 로드맵 06 후보

- **몬스터의 길찾기** — 막히면 두드릴 뿐 우회하지 않는다(ADR 0019가 감수한 것)
- **동굴의 깊이** — 한 층이라 갈수록 같은 그림이다. ADR 0013의 맵 모델이 열려 있다
- **모바일·터치** — 로드맵 05 Phase 1이 마우스를 완결해 가까워졌다. 화면 크기와 배치가 남았다
- **날씨·계절** — 세 로드맵째 미뤘다. 그것을 필요로 하는 시스템이 아직 없다
- **저장 슬롯 여러 개** — 단일 슬롯이 불편하다는 말이 아직 나온 적 없다(ADR 0008)
- **외부 아트 에셋** — 코드 생성이 아직 버틴다(ADR 0009)

## 4. 이어서 일할 사람을 위한 실무 정보

### 명령

```sh
npm install
npm test            # 941개, 23초
npm run typecheck
npm run build       # 타입 검사 + 프로덕션 빌드(/game-dev1/ 경로)
npm run dev         # 개발 서버. 확인용으로만 쓰고 끝나면 끈다
```

### 화면 확인 방법 (중요)

브라우저 확장을 쓸 수 없으므로 **헤드리스 크롬을 CDP로 직접 몰았다.** 이 방식으로 이번
로드맵들에서 화면으로만 드러나는 결함을 **열 개 넘게** 찾았다.

1. `google-chrome --headless=new --remote-debugging-port=9222 --no-sandbox --disable-gpu
   --window-size=1280,800 --user-data-dir=/tmp/claude-chrome-profile about:blank`
2. `http://127.0.0.1:9222/json/list`에서 페이지 대상을 찾아 WebSocket으로 CDP 연결
   (Node 24에는 `WebSocket`이 내장돼 있어 의존성이 필요 없다)
3. `Page.navigate` → `Runtime.evaluate` → `Input.dispatchKeyEvent` /
   `Input.dispatchMouseEvent` → `Page.captureScreenshot`
4. 끝나면 서버와 크롬을 **반드시 정리한다**

**개발 훅**: 개발 모드에서만 `window.__town`에 `{ game, camera, world, effects, toasts,
router, help }`가 노출된다(`src/main.ts`, `import.meta.env.DEV` 가드). 밤·침입·동굴처럼
한참 키워야 나오는 화면을 이것으로 곧바로 만든다. 프로덕션 빌드에서는 사라진다.

**주의**: `localStorage.clear()` 뒤 새로고침하면 `pagehide` 저장이 옛 상태를 다시 써 버린다.
새 판이 필요하면 저장 메뉴의 "새로 시작"을 누르고 확인 버튼("한 번 더")까지 눌러야 한다.

### 밸런스를 재는 방법

`test/playthrough.test.ts`의 봇이 유일한 측정 수단이다. 콘솔에 레벨·시간·건물 종류·구간
시각이 찍힌다. **새 시스템을 넣으면 봇이 그것을 쓰게 만들어야 한다** — 이 규칙을 세 번
어겼고 세 번 다 측정이 거짓이 될 뻔했다(로드맵 02 Phase 6, 03 Phase 8, 05 Phase 5).

### 지켜 온 규칙

- 모든 함수에 주석. 기능 뒤에 테스트. 되돌리기 비싼 결정은 ADR. Phase 단위 커밋
- **파생값은 저장하지 않는다** — 레벨에서 나오는 보너스, 누적 시간에서 나오는 시각,
  지형에서 나오는 통로 위치(ADR 0011·0013·0015)
- **저장 형식은 선택적 필드로 늘린다.** 로드맵 03 이후 형식 버전은 2에서 그대로다
  (ADR 0008 개정)
- **새 상호작용은 키보드로도, 마우스로도 닿아야 한다**(ADR 0012, 로드맵 05 Phase 1)
- **도형 렌더링을 지우지 않는다** — 헤드리스 테스트가 그 위에서 돈다(ADR 0009)
- **확인은 만드는 쪽이 한다.** 사용자에게 "열어서 봐 달라"고 넘기지 않는다

## 5. 알려진 한계 (ADR이 감수한 것들)

| 무엇 | 어디에 적혀 있나 |
|---|---|
