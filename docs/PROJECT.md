# 프로젝트 목표 및 시스템 개발 명세서 (Project Specification)

**프로젝트 명칭:** Project MicroVillage (가칭)  
**문서 버전:** v1.0.0  
**문서 상태:** Approved (기준 문서)  
**대상 플랫폼:** Web Browser (Desktop First, HTML5 Canvas / WebAssembly 확장 가능)  
**장르:** 2D 그리드 기반 식민지/마을 건설 시뮬레이션 (Colony & Village Builder)

---

## 1. 프로젝트 비전 및 핵심 설계 원칙

### 1.1 프로젝트 개요
별도의 설치나 플러그인 없이 웹 브라우저에서 즉시 실행 가능한 **가볍고 확장성 높은 2D 타일 기반 마을 건설 시뮬레이션 게임**을 구축한다. 플레이어는 지형 위에 인프라(도로, 주택, 작업장, 창고)를 건설하고, 자율 주민 AI는 마을의 시설과 자원을 유기적으로 활용하여 자급자족 공동체를 성장시킨다.

### 1.2 핵심 설계 원칙 (Core Pillars)
* **간접 제어 기반 자율 시뮬레이션 (Emergent Agent Simulation):** 플레이어는 주민을 직접 조작(RTS식 직접 이동 명령)하지 않고, 인프라 건설과 우선순위 지정, 구역 설정을 통해 간접적으로 주민의 행동을 유도한다.
* **명확한 물리적 물류 흐름 (Physical Logistics):** 모든 자원은 순간이동(Teleportation)하지 않으며, 물리적인 운반(채집 $\rightarrow$ 운반 $
ightarrow$ 보관 $
ightarrow$ 시공/소비) 과정을 거친다. 도로망 단절이나 병목은 생산 마비로 이어진다.
* **점진적 확장 구조 (Scalable Progression):** 단순한 생존과 채집으로 시작하여, 직업 분화 $\rightarrow$ 가공 생산 체인 $\rightarrow$ 인구 및 주거 안정화로 시스템이 심화된다.
* **견고한 틱/렌더 분리 (Decoupled Game Loop):** 논리 시뮬레이션(Fixed Tick)과 시각적 렌더링(Interpolated Render)을 분리하여 저사양 웹 환경에서도 일관된 시뮬레이션 무결성을 보장한다.

## 2. 시스템 아키텍처 및 게임 루프

```
+-------------------------------------------------------------------+
|                           Game Engine                             |
|  +-----------------------------+   +---------------------------+  |
|  |   Fixed Tick (Logic, 20Hz)  |   |   Render Loop (60+ FPS)   |  |
|  | - 주민 AI 상태 머신(FSM)    |   | - 뷰포트 컬링 및 타일 렌더 |  |
|  | - 자원 생산/소비/운반 틱    |   | - 엔티티 위치 보간(Lerp)  |  |
|  | - A* 경로 탐색 큐 처리      |   | - UI/HUD 및 오버레이      |  |
|  +-----------------------------+   +---------------------------+  |
|                                 ^                                 |
|                                 | Event Bus                       |
|  +-------------------------------------------------------------+  |
|  |                   Core State & Managers                     |  |
|  | - GridMap (지형/충돌/비용)      - BuildingManager (구조물)    |  |
|  | - VillagerManager (주민/작업)  - ResourceManager (창고/재고) |  |
|  +-------------------------------------------------------------+  |
+-------------------------------------------------------------------+
```

### 2.1 Fixed Timestep 시뮬레이션 루프
* **논리 틱 (Logic Tick - 20 TPS, dt = 50ms):**
  * 주민 욕구(배고픔, 피로도) 갱신 및 FSM 상태 전이.
  * A* 경로 탐색 큐(Time-sliced Pathfinding) 순차 연산.
  * 작업장 생산 주기 및 창고 재고 예약/차감.
* **렌더 루프 (Render Loop - requestAnimationFrame):**
  * 카메라 뷰포트 내 타일 및 스프라이트 렌더링(화면 밖 객체 컬링).
  * 주민 좌표 선형 보간(`renderX = prevX + (currX - prevX) * alpha`).

## 3. 핵심 서브시스템 명세

### 3.1 타일 그리드 및 네비게이션 시스템
맵은 2차원 사각 격자(Orthogonal Grid) 구조이며, 다중 레이어 데이터 모델을 채택한다.

| 레이어 | 저장 데이터 | 주요 역할 |
|---|---|---|
| **Terrain Layer** | 잔디, 흙, 물, 암반 | 기본 통과 여부(Passable) 및 이동 가중치(Cost) 결정 |
| **Resource Layer** | 나무, 바위, 베리 덤불 | 주민이 채집 가능한 고갈형 천연 자원 노드 |
| **Structure Layer**| 도로, 주택, 작업장, 창고 | 플레이어 건설물, 충돌 영역(Footprint), 입구 타일(Entrance) |
| **Nav Cost Layer** | 통합 이동 비용 맵 (Float) | A* 알고리즘이 실시간 참조 (도로: 0.5, 평지: 1.0, 진흙: 2.0 등) |

* **좌표계 변환:**
  * 화면 스크린 좌표 $(x, y) \longleftrightarrow$ 뷰포트 월드 좌표 $\longleftrightarrow$ 그리드 셀 좌표 $(\text{col}, \text{row})$
* **카메라 컨트롤:**
  * 이동(Pan): 마우스 드래그(우클릭/휠클릭) 및 WASD / 방향키
  * 줌(Zoom): 마우스 휠 스크롤 ($0.5\times \sim 2.0\times$)

---

### 3.2 건설 및 공간 점유 시스템

* **구조물 풋프린트(Footprint) 모델:**
  * 점유 타일(Occupied Area): 구조물이 실제 차지하는 $W \times H$ 격자 영역 (보행 불가 처리).
  * 입구 타일(Entrance Point): 주민이 상호작용하기 위해 진입해야 하는 인접 $1 \times 1$ 타일.
* **배치 유효성 검증 (Placement Validation):**
  1. 점유 영역 전체가 건설 가능한 지형(Buildable)인가?
  2. 타 구조물이나 통과 불가 자원 노드와 겹치지 않는가?
  3. 입구 타일이 외부 통과 가능 타일(Walkable)과 최소 1면 이상 연결되는가?
  4. 창고에 즉시 지불 가능한 건설 자원이 충분한가?
* **건설 라이프사이클:**
  $$\text{미리보기(Preview)} \longrightarrow \text{청사진(Blueprint)} \longrightarrow \text{자원 운반} \longrightarrow \text{시공(Work)} \longrightarrow \text{완공(Active)}$$

### 3.3 주민 AI 및 행동 루프 시스템

```
                  +--------------------------+
                  |           IDLE           |
                  +--------------------------+
                    /           |          \
    (피로도 한계 도달) /            | (작업 배정) \ (자원 운반 필요)
                   v            v            v
        +--------------+ +--------------+ +--------------+
        | WALK_TO_HOME | | WALK_TO_WORK | | WALK_TO_NODE |
        +--------------+ +--------------+ +--------------+
               |                |                |
               v                v                v
        +--------------+ +--------------+ +--------------+
        |   RESTING    | |   WORKING    | |  HARVESTING  |
        +--------------+ +--------------+ +--------------+
               \                |                /
                \               v               /
                 +-----> [ 행동 완료 / 복귀 ] <---+
```

* **욕구 및 상태 메커니즘:**
  * **피로도 (Energy, 0~100):** 작업 시 지속 소모, 임계치(20 이하) 도달 시 작업 중단 후 집으로 이동하여 회복.
  * **배고픔 (Hunger, 0~100):** 시간 비례 소모, 임계치 이하 시 창고나 집에서 식량 섭취.
* **자원/작업 예약 시스템 (Resource Reservation):**
  * 두 명 이상의 주민이 동일한 자원 노드나 창고 슬롯을 목표로 중복 이동하는 것을 방지하기 위해 단일 소유권 예약(Exclusive Lock) 적용.

---

### 3.4 자원 경제 및 생산 물류 체인

```
[천연 자원 노드] (나무/바위/농작물)
       │ (주민 채집)
       ▼
[인벤토리/바닥] (이동식 자원)
       │ (주민 운반 - Hauling)
       ▼
[중앙 저장 창고] (공용 가용 자원 풀)
       │ (신규 건설/생산 가공 시 차감)
       ▼
[건설 현장 / 2차 가공 시설]
```

* **자원 유형:**
  * 1차 기본 자원: 목재(Wood), 석재(Stone), 식량(Food)
  * 2차 가공 자원: 판자(Plank), 가공석(Cut Stone), 빵(Bread)
* **물류 규칙:**
  * 자원은 창고에 보관된 시점부터 전체 정산 시스템에 반영.
  * 창고 용량이 포화 상태일 경우 추가 채집 및 생산 중단.

## 4. 단계별 개발 마일스톤 및 로드맵

```
Phase 1 (MVP)         Phase 2               Phase 3               Phase 4               Phase 5               Phase 6
[기초 루프 확립] ───> [건설/그리드 고도화] ───> [주민 AI & FSM] ───> [자원 & 물류 경제] ───> [UI/UX 시스템 완성] ──> [콘텐츠 확장 & 폴리싱]
 - 타일 렌더러          - 다중 타일 점유       - A* 경로 탐색         - 자원 노드/채집        - HUD 자원바           - 생산 체인 복합화
 - 1명 주민 이동         - 입구 타일 검증       - 집-일터 왕복 FSM     - 창고 입출고          - 건설 카테고리 메뉴    - 세이브/로드 (JSON)
 - 집/작업장 배치       - 회전 및 철거         - 피로도 기반 휴식      - 운반(Hauling) 로직   - 인스펙터 정보창      - 게임 밸런싱
```

### 마일스톤 세부 내역

* **Phase 1: 최초 플레이 가능 프로토타입 (MVP Milestone)**
  * $20 \times 20$ 캔버스 타일 맵 렌더링 및 타일 마우스 인터랙션.
  * 단일 타일 주택(House) 및 작업장(Workplace) 배치.
  * 주민 1명의 A* 경로 이동 및 상태 전이(`IDLE` $\rightarrow$ `WORKING` $\rightarrow$ `RESTING`).
* **Phase 2: 그리드 및 건설 엔진 확장**
  * $2\times2$, $3\times3$ 다중 타일 점유 및 입구 타일 지정 로직.
  * 도로 타일 시스템(이동 비용 감소 버프) 및 구조물 철거(Demolish).
* **Phase 3: 주민 AI 및 멀티 에이전트 확장**
  * 다수 주민 지원 및 Time-sliced 경로 탐색 큐.
  * 피로도/배고픔 기반 욕구 시스템 및 침대 배정.
* **Phase 4: 자원 노드 및 물리 물류 시스템**
  * 맵 상의 천연 자원(나무, 바위) 생성 및 채집 로직.
  * 창고 보관량 관리 및 운반(Hauling) 전담 AI.
  * 신규 건설 시 창고 자원 반출 $\rightarrow$ 현장 운반 $\rightarrow$ 착공.
* **Phase 5: HUD 및 인스펙터 UI 완성**
  * 상단 자원 현황 바 및 시간 배속 컨트롤 ($0\times, 1\times, 2\times, 4\times$).
  * 타일 / 구조물 / 주민 클릭 시 상세 정보 사이드바.
* **Phase 6: 생산 체인 심화 및 시스템 안정화**
  * 2차 가공 시설(풍차, 제재소 등) 및 고급 생산 체인.
  * JSON 기반 로컬 스토리지 Save/Load 지원.
  * 오디오 및 스프라이트 애니메이션 적용.

## 6. 기술적 위험 요소 및 대응 전략

| 위험 요소 (Risk) | 영향도 | 기술적 대응 전략 |
|---|---|---|
| **다수 주민 경로 탐색 병목** | 높음 | • 분산 연산(Time-sliced Pathfinding): 틱당 최대 N개 경로만 계산<br>• 동일 목적지 집단 이동 시 Flow Field 네비게이션 도입 검토<br>• 지형 변경 시에만 네비게이션 그래프 갱신 |
| **자원 중복 타깃팅 (Race Condition)** | 중간 | • 작업 대상(나무, 바위, 창고 슬롯)에 주민 ID를 Lock하는 예약 시스템 적용<br>• 예약된 대상은 다른 주민의 탐색 쿼리에서 자동 필터링 |
| **프레임레이트 변동 시 시뮬레이션 오차** | 높음 | • 고정 시간 간격(Fixed Timestep, 20 TPS) 시뮬레이션 강제<br>• 렌더 루프에서는 위치 선형 보간(Lerp)만 수행하여 화면 끊김 방지 |
| **세이브 데이터 구조 파편화** | 낮음 | • 모든 객체를 직렬화 가능한 Plain Object(JSON) 구조로 설계<br>• `schemaVersion` 필드를 통해 버전별 데이터 마이그레이션 함수 제공 |
