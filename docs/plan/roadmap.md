# 타운빌더 개발 로드맵 (MVP)

본 문서는 `docs/plan/project.md` 기획서를 실제 구현 순서로 분해한 작업 계획이다.
목표는 기획서 8절의 **MVP 범위**를 완성하는 것이며, 그 바깥의 항목은 이 로드맵에 포함하지 않는다.

## 0. 진행 원칙

- **수직 슬라이스 우선**: 각 Phase가 끝날 때마다 브라우저에서 실제로 눈에 보이고 조작 가능한 결과물이 남는다. "나중에 합치는" 모듈 단위 선개발은 하지 않는다.
- **테스트 동반**: 순수 로직(좌표 변환, 지형 자료구조, 인벤토리, 레벨 계산)은 기능 구현 직후 단위 테스트를 작성한다. 렌더링/입력은 수동 확인으로 대체한다.
- **기술 결정은 ADR**: 스택 선정, 자료구조 설계, 좌표계 규약 등 되돌리기 비싼 결정은 `docs/adr/`에 기록한다.
- **Phase 단위 커밋**: 각 Phase의 산출물이 동작하는 시점에 commit 및 push 한다.

## 1. 의존 관계

```
Phase 0 기반
   └─ Phase 1 아이소메트릭 렌더링
         ├─ Phase 2 복셀 지형 (파기/쌓기)
         │     └─ Phase 6 건축 (평탄지 판정에 의존)
         └─ Phase 3 플레이어 이동/조작
               └─ Phase 4 채집 ── Phase 5 인벤토리/창고
                                       └─ Phase 6 건축
                                             └─ Phase 7 NPC ── Phase 8 마을 레벨
                                                                    └─ Phase 9 UI 폴리싱
```

Phase 2와 Phase 3은 Phase 1 완료 후 병렬 진행이 가능하다. 그 외는 직렬이다.

---

## Phase 0 — 프로젝트 기반

**목적**: 코드를 작성하고 실행하고 테스트할 수 있는 최소 골격 확보.

| 작업 | 산출물 |
|---|---|
| 기술 스택 결정 | `docs/adr/0001-기술-스택-선정.md` |
| 디렉토리 구조 확정 | `src/core`, `src/render`, `src/sim`, `src/ui`, `test/` |
| 실행 진입점 | `index.html`, `src/main.js` — 빈 캔버스가 화면에 뜬다 |
| 테스트 러너 | `npm test`로 단위 테스트 실행 |
| 게임 루프 | 고정 timestep 업데이트 + requestAnimationFrame 렌더 분리 |

**완료 기준**: 브라우저에서 검은 캔버스와 FPS 표시가 뜨고, `npm test`가 통과한다.

**결정 필요**: 기술 스택 (Vanilla JS + Canvas / TypeScript + Canvas / Phaser 3 / Three.js). 기획서 3절이 "카메라 회전 없는 고정 각도"를 명시하므로 진짜 3D는 불필요하다. 2D Canvas 계열을 권장하며, 최종 선택은 ADR에서 확정한다.

## Phase 1 — 아이소메트릭 렌더링 기반

**목적**: 타일 그리드를 쿼터뷰로 화면에 그리고, 마우스로 타일을 집어낼 수 있게 한다.

- 좌표 변환 유틸: 그리드 좌표(x, y, z) ↔ 화면 좌표(screenX, screenY) 양방향 변환
- 타일 스프라이트(또는 색상 마름모) 렌더링, 깊이 정렬 규칙 확립
- 카메라: 팬(드래그), 줌 인/아웃. **회전은 지원하지 않는다**
- 마우스 피킹: 커서 아래 타일 좌표 산출 → 하이라이트 표시
- 화면 밖 타일 컬링

**테스트**: 좌표 변환 왕복(round-trip) 검증, 경계값 검증, 깊이 정렬 순서 검증.

**완료 기준**: 마름모 타일 그리드가 표시되고, 드래그로 이동/휠로 줌이 되며, 마우스 올린 타일이 하이라이트된다.

**ADR 후보**: 타일 크기 및 좌표계 규약(원점 위치, z축 방향, 타일 픽셀 치수).

---

## Phase 2 — 복셀 지형: 파기와 쌓기

**목적**: 기획서 5.1의 지형 시스템 구현.

- 지형 자료구조: `width × height × 5레이어` 블록 그리드, 블록 타입(흙/돌/철광석/빈칸)
- 높이 있는 지형 렌더링(측면 벽면 포함) 및 올바른 깊이 정렬
- **파기**: 블록 제거 → 해당 자원 획득, 아래 레이어 노출
- **쌓기**: 보유 블록을 인접 유효 위치에 배치
- 깊이 제한 5레이어 강제
- **평탄도 판정 함수**: 지정한 사각 영역이 같은 높이의 빈 지면인지 검사 (Phase 6 건축의 전제 조건)

**테스트**: 파기/쌓기 후 지형 상태 검증, 5레이어 초과 파기 거부, 평탄도 판정의 참/거짓 케이스.

**완료 기준**: 클릭으로 땅을 파고 다시 메울 수 있고, 높낮이가 화면에 정상적으로 보인다.

**ADR 후보**: 지형 자료구조 설계(3D 배열 vs 높이맵+타입맵), 렌더링 성능 전략.

---

## Phase 3 — 플레이어와 조작

**목적**: 조작 가능한 캐릭터를 세운다.

- 플레이어 스프라이트 렌더링 및 지형 위 배치(높이 반영)
- 그리드 기반 이동(키보드), 이동 불가 지형 충돌 처리
- 도구 슬롯 선택(도끼/곡괭이/삽) 및 타격 액션
- 상호작용 대상 판정: 플레이어 인접 타일만 채집/파기 가능

**완료 기준**: 캐릭터를 걷게 하고, 인접한 땅만 팔 수 있다.

---

## Phase 4 — 자원 채집

**목적**: 기획서 5.2의 채집 루프 구현. MVP 자원 3종은 목재/돌/철광석.

- 나무·광맥 오브젝트를 맵에 배치
- 타격 → 내구도 감소 → 파괴 → 자원 드롭
- 나무 리스폰 타이머
- **도구 등급 체계**: 초급/중급/고급. 채집 속도 배수 및 자원별 최소 도구 등급 요구 (철광석은 중급 이상)

**테스트**: 채집 판정(도구 등급 부족 시 거부), 드롭 수량, 리스폰 타이머.

**완료 기준**: 나무를 베어 목재를, 광맥을 캐서 돌/철광석을 얻는다.

---

## Phase 5 — 인벤토리와 창고

**목적**: 자원을 담고 꺼내는 저장소.

- 인벤토리 자료구조(슬롯/스택 규칙) 및 용량 제한
- 창고: 마을에 배치된 공용 저장소. 인벤토리 ↔ 창고 이동
- 하단 인벤토리 바 UI

**테스트**: 스택 병합/분할, 용량 초과 처리, 창고 입출고.

**완료 기준**: 채집한 자원이 인벤토리 바에 보이고, 창고에 옮길 수 있다.

---

## Phase 6 — 완성형 건축 시스템 (핵심 차별점)

**목적**: 기획서 5.3 구현. 블록 조립이 아닌 즉시 완공 방식.

- 블루프린트 데이터 정의: 필요 자재 목록 + 바닥 면적. MVP 5종 — 집 2종, 창고, 우물, 작업대
- 건축 모드 진입 → 블루프린트 목록 UI (보유 자재 대비 부족분 빨간색 표시)
- 반투명 고스트 미리보기 + 배치 가능/불가 시각 피드백
- 배치 검증: **평탄한 빈 지면**(Phase 2의 판정 함수) + 다른 건물과 미충돌
- 확정 시 자재 소모 → 3~5초 "건축 중" 연출(게이지) → 완성 건물로 전환
- 건물 렌더링 및 점유 타일 관리

**테스트**: 자재 부족 시 건축 거부, 자재 정확히 차감, 비평탄/점유 위치 배치 거부.

**완료 기준**: 자재를 모아 집을 짓고 마을에 건물이 남는다.

**ADR 후보**: 블루프린트 데이터 정의 방식(JSON 데이터 파일 vs 코드 상수).

---

## Phase 7 — NPC 이주와 요청

**목적**: 기획서 5.4 구현. 대사·컷신 없이 알림과 아이콘만 사용한다.

- 집 완공 + 마을 레벨 조건 충족 → NPC 자동 이주, "새 주민이 이주했습니다" 토스트
- NPC 단순 배회 AI (경로 탐색은 최소 구현)
- **요청 시스템**: MVP 요청 유형 2~3종
  - 자재 납품형 ("목재 5개를 주세요")
  - 시설 건축형 ("우물이 필요해요")
- 요청 수락/완료 판정 → 보상(마을 레벨 경험치) 지급
- 상단 미완료 요청 아이콘 리스트

**테스트**: 이주 조건 판정, 요청 생성/완료 판정, 보상 지급.

**완료 기준**: 집을 지으면 주민이 들어오고, 요청을 완료해 보상을 받는다.

---

## Phase 8 — 마을 레벨과 해금

**목적**: 기획서 6절의 진행 구조. MVP는 레벨 1~5.

- 마을 레벨 산정: 건물 수 + 주민 수 + 요청 완료 수 누적치
- 레벨업 시 해금: 새 블루프린트, 새 채집 구역, 상위 도구
- 채집 구역 단계적 개방 (초원 → 숲 → 산악)
- 상단 마을 레벨 게이지 + 1차 목표 상시 노출

**테스트**: 레벨 산정 공식, 레벨업 임계값, 해금 항목 적용.

**완료 기준**: 마을을 키워 레벨 5까지 도달하고, 도중에 새 블루프린트가 해금된다.

---

## Phase 9 — UI/UX 폴리싱과 밸런싱

**목적**: 기획서 7절 충족 및 플레이 가능한 상태로 다듬기.

- 토스트 알림 시스템 통합 (**대사창은 만들지 않는다**)
- 하단 바: 인벤토리 + 채집/건축 모드 전환 버튼
- 건축 중 먼지 이펙트 등 최소 연출
- 자원 수급 밸런싱: 채집 속도 대비 블루프린트 요구량 조정
- 성능 점검: 타일 수 증가 시 프레임 유지

**완료 기준**: 처음 실행해서 레벨 5까지 막힘 없이 플레이된다.

---

## 2. MVP 이후 (이 로드맵 범위 밖)

기획서 8절의 제외 항목과 9절 확장 아이디어는 MVP 완료 후 별도 계획으로 다룬다: 전투/몬스터, 건물 커스터마이징, 다중 맵, 날씨/낮밤 사이클, NPC 직업 배정.

**단, 세이브/로드는 기획서에 명시되지 않았으나 플레이 지속성에 필요하다.** Phase 8 이후 도입 여부를 별도로 판단한다.
