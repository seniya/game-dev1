# 타운빌더 개발 로드맵 06 — 사람답게 걷는 마을

- **선행**: `roadmap_01.md`~`roadmap_05.md`
- **기획서**: `docs/plan/project.md`
- **시작일**: 2026-09-04

## 목표

마을에는 주민과 플레이어가 있지만, 지금 화면에서 이들은 색만 다른 정적 말이고 타일
사이를 일정한 속도로 미끄러진다. 건물과 지형은 질감·높이·그림자를 갖는데, 가장 자주
보는 캐릭터가 그 수준에 닿지 못해 마을 전체가 어색하게 느껴진다.

이번 로드맵은 콘텐츠를 더하지 않는다. **캐릭터를 읽을 수 있게 만들고, 걸음이 이동 규칙과
같은 리듬을 갖게 하는 것**이 목표다.

| 항목 | 현재 | 목표 |
|---|---|---|
| 플레이어·주민 | 몸통과 머리만 있는 정적 말 | 다리·팔·머리 방향이 읽히는 보행 포즈 |
| 이동 | 일정한 속도의 선형 보간 | 출발·도착에서 자연스러운 가감속 |
| 움직임과 그림 | 이동해도 같은 스프라이트 | 실제 이동 진행도와 보행 포즈가 연동 |
| 확인 | 단위 테스트 중심 | 포즈·보간 단위 테스트와 브라우저 장면 확인 |

## 원칙

- **논리 이동 규칙은 바꾸지 않는다.** 한 칸, 4방향, 충돌과 도착 시점은 그대로다. 바뀌는 것은
  렌더용 위치 곡선과 모습뿐이다.
- **움직임 정보는 저장하지 않는다.** 방향과 보행 진행도는 현재 이동 상태에서 나오는 일시값이다.
  저장을 다시 열면 정지 자세로 시작한다.
- **주민과 플레이어는 같은 운동 언어를 쓴다.** 속도·크기는 달라도, 한쪽만 미끄러지거나
  한쪽만 사람처럼 걸어서는 안 된다.
- **스프라이트를 계속 코드로 만든다.** 외부 아트 의존성을 추가하지 않고 ADR 0009의 헤드리스
  도형 폴백도 유지한다.
- **모든 변경은 테스트와 화면 확인을 함께 한다.** 숫자 테스트만 통과해도 시각적 어색함은
  남을 수 있으므로 실제 브라우저에서 걷기·경사·주민 밀집 장면을 확인한다.

## 의존 관계

```
Phase 1 이동 감각과 보행 포즈
      └─ Phase 2 화면에서 캐릭터를 읽게 하기
              └─ Phase 3 실제 플레이 관찰과 미세 조정
```

## Phase 1 — 이동 감각과 보행 포즈 (완료)

> **완료(2026-09-04).** `actorMotion`의 smoothstep 보간과 4방향 pose를 플레이어·주민에
> 넣고, 절차적 스프라이트·도형 폴백 모두가 걸음 진행도에 맞춰 다리·팔·몸통을 그리게 했다.
> 실제 브라우저에서 정지·동쪽 보행 장면을 확인했다. 테스트는 941개에서 **948개**가 됐다.

**목적**: 플레이어와 주민이 멈춰 있다가 걸음을 떼고, 발을 번갈아 옮겨 도착한다.

### 작업

- 선형 이동 보간을 smoothstep 가감속 곡선으로 바꾼다. 논리적 도착 시각은 유지한다.
- 이동 중인 방향·진행도를 `pose`에 담고 렌더러로 전달한다.
- 절차적 스프라이트에 두 다리, 팔, 진행도별 몸통 높이, 바라보는 방향을 넣는다.
- 스프라이트가 없는 헤드리스 폴백에도 같은 실루엣과 보행 리듬을 반영한다.
- 플레이어·주민의 보간 곡선, 방향, 스프라이트 선택을 테스트한다.

**완료 기준**: 보통 확대율에서 한 칸 이동이 "미끄러짐"으로 보이지 않고, 플레이어와 주민이
같은 보행 언어로 읽힌다. 기존 이동·저장·통과 플레이 테스트가 유지된다.

## Phase 2 — 화면에서 캐릭터를 읽게 하기

**목적**: 복잡한 마을·밤·동굴에서도 플레이어, 주민, 몬스터의 역할이 즉시 구분된다.

### 작업

- 플레이어의 실루엣·색 대비와 주민의 색상 범위를 실제 화면에서 점검한다.
- 밤과 동굴, 건물 안, 주민이 겹친 장면을 캡처해 가독성을 확인한다.
- 필요할 때만 작은 상태 표식(일하는 주민 등)을 검토한다. 아이콘 과잉은 피한다.

**완료 기준**: 세 장면(낮 마을, 밤, 동굴)에서 플레이어를 즉시 찾고 주민·몬스터를 혼동하지 않는다.

## Phase 3 — 실제 플레이 관찰과 미세 조정

**목적**: 만든 쪽의 인상이 아닌 플레이 중의 리듬으로 마무리한다.

### 작업

- 걷기, 연속 이동, 도구 휘두르기, 출퇴근, 주민 밀집을 실제로 플레이해 본다.
- 이동 시간·포즈 진폭·주민 대기 시간이 게임 템포를 해치지 않는지 봇과 브라우저에서 확인한다.
- 발견된 한두 가지 마찰만 고치고, 새 애니메이션 시스템으로 범위를 키우지 않는다.

**완료 기준**: 화면 확인 기록, 테스트, ADR, 상태 인수 기록을 남기고 Phase 단위로 커밋·푸시한다.

## 이번 로드맵에서 하지 않는 일

- 스켈레탈 애니메이션, 외부 아트 팩, 대각선 이동, 경로 탐색을 넣지 않는다.
- 이동 규칙이나 충돌 판정을 시각 개선 명목으로 바꾸지 않는다.
- 몬스터 AI와 전투 깊이는 다음 콘텐츠 로드맵의 후보로 남긴다.
