# v0.5.1 장기 관측 결과

`npm run regression`이 `regression.json`을 다시 생성한다. 시뮬레이션 결과와 실행 조건은 결정적이며 생성 시각·실행 시간·프로세스 메모리는 실행 환경에 따라 달라진다.

2026-09-29 검증: 18개 조건과 100일 Mock 실행 통과. 모든 조건에서 식량/목재/코인 회계 오차 0, 중간 저장 후 이어 실행과 독립 재실행의 SHA-256 동일, 저장 참조/범위 검증 통과, 하루 이상 지속된 미완료 행동 0.

가뭄 조건은 처음 10번의 일별 구간 시작마다 3일 가뭄을 갱신하고, 11번째 구간에 식량 24개를 투입한다. 새 가뭄 갱신을 멈춘 후에도 마지막 개입 기간이 끝날 때까지 가뭄이 남는다. 100명 조건은 농장/자연 자원/시장 기금을 추가하지 않는다. 사망 사건의 실제 ID, 틱, 욕구/소지 식량/창고/날씨는 `deathEvidence`에 기록한다.

Mock / seed 42 / 100일: 생존 12, 공유 24, 절도 2, 갈등 8, 거래 143, 임금 총 63코인, 승인 해석 58, 사건 40,932.

관찰된 한계도 다음 단계의 입력이다. 정상 조건에서는 최대 단계 농장과 재생 자원 때문에 식량/목재가 지속적으로 쌓이고, 식량 가격은 하한 1에 이른다. 시장 기금은 초반에 소진될 수 있다. 이것은 무한 임금이나 회계 누락이 아니라 수요 대비 공급/공동 인출 규칙의 결과다. 여러 마을의 교역·인구 증가·소비처 확장을 검토할 때 기준선으로 사용한다.

365일 저장 파일은 이 조건들에서 약 5.2~75.6MB다. 저장과 사건 전체 복제는 장기 브라우저 실행의 병목이므로 서버 아카이브/페이지 조회가 다음 우선순위다. `processHeapMB`는 회귀 검증 프로세스 전체에서 여러 세계 사본과 GC 대기 객체를 포함하며 단일 세계의 메모리 크기가 아니다. `elapsedMs`도 원 실행 외 저장/복원/재실행 검증 비용을 포함한다.
